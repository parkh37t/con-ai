# screen-inventory — 최대 화면 본수 체크·정리

> 와일리 OS 인테이크 보조. 사이트의 **화면 총량**을 최대한 빠짐없이 모으고, 유형·포털·메뉴로 분류해 **카탈로그**로 산출한다(s2b2 통합 인덱스 방식 참고: 약 1,428화면).
> 원칙: **수집 못 한 영역은 0이 아니라 '미수집'으로 명시.** 본수에 추정 끼워넣기 금지.

## 입력
- 대상 도메인/URL. 프로젝트 slug.

## 절차

### 1. URL 풀 최대 수집 (다중 모달)
- **sitemap 전수**: `robots.txt`의 모든 `Sitemap:`, sitemap-index 하위 전부 fetch(가장 신뢰).
- **링크 크롤**: 동일 도메인 BFS(depth·rate-limit·robots 준수)로 sitemap 누락분 보강.
- **검색엔진 보조**: `site:도메인` WebSearch로 색인된 추가 URL 확인.
- 대규모면 **서브에이전트 팬아웃**(섹션/sitemap별 병렬 수집) — 각 결과를 합집합.

### 2. 정규화 (본수 부풀림 차단)
- 쿼리스트링/세션/앵커/추적 파라미터 제거.
- **동적 URL 폭발은 템플릿 단위로 집계**: `/goods/123`, `/goods/456` → `/goods/{id}` 1 화면유형(대표 + 인스턴스 수 별도).
- 페이지네이션(`?page=N`)·정렬·필터 변형은 1 화면으로 병합.
- 중복 제거 후 **고유 화면 수** 확정.

### 3. 분류·화면ID
- 유형 추정: `list`/`detail`/`form`/`popup`/`landing`(URL 패턴·동사·접미사 기반).
- 포털/섹션: 1depth path로 그룹(예: 구매자/공급자/관리자).
- 화면ID 부여(명명규칙): `<포털>-<섹션>-<기능>` 또는 프로젝트 규칙. 화면명은 `<title>`/메뉴 라벨.

### 4. 산출 (카탈로그)
- `projects/<slug>/inventory/screen-list.csv` — `화면ID, 화면명, URL, 유형, 포털, 섹션, source, 비고`.
- `projects/<slug>/inventory/index.html` — 검색·필터 가능한 HTML 카탈로그(s2b2 인덱스 스타일: 그룹·뱃지·건수).
- **집계 요약**: 고유 화면 수 · 유형별/포털별 분포 · 템플릿형 인스턴스 수.

### 5. 커버리지·한계
- 수집 출처별 건수(sitemap N / 크롤 M / 검색 K)와 합집합 명시.
- 미수집: JS 라우트(SPA), 로그인 뒤, robots 차단, 무한스크롤 → 항목별 표기.
- "최대한"의 경계를 정직하게: **무엇을 못 셌는지** 반드시 적는다(silent 누락 금지).

## 산출물 골격
```
projects/<slug>/inventory/
├── screen-list.csv   # 화면 카탈로그(원장)
└── index.html        # 검색·필터 카탈로그 뷰
```

## 함정
- 파라미터 URL 폭발 → 템플릿 집계(인스턴스 수는 메타로만).
- sitemap이 최신이 아닐 수 있음 → 크롤·검색으로 교차검증.
- 다국어/모바일 별도 URL(`/en/`, `/m/`)은 변형으로 묶고 별도 카운트.
- `ia-from-url`(구조)과 짝: 본수=inventory, 계층=IA.
