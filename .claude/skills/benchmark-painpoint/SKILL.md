# benchmark-painpoint — 벤치마킹 → 페인포인트·개선 도출

> 와일리 OS 리서치 단계. 유사 사이트를 **벤치마킹**하고, 대상 사이트의 **페인포인트**를 근거와 함께 도출해 **개선사항**을 우선순위로 정리한다.
> 원칙(`방법론/와일리-OS/04_knowhow.md`): **모든 주장은 출처(URL/스크린샷) 그라운딩.** 주관 인상 금지 — 휴리스틱 체크리스트로 객관화.

## 입력
- 대상 사이트 URL + 업종/목적. 프로젝트 slug.

## 절차

### 1. 유사 사이트 식별 (리서치)
- WebSearch로 동종 업종·경쟁/베스트프랙티스 사이트 3~5개 선정(근거 명시: 시장점유·수상·레퍼런스).
- 비교 축 정의: IA 깊이, 핵심 플로우(검색→상세→전환), 정보밀도, 반응형, 접근성.

### 2. 벤치마킹 (수집·구조화)
- 각 사이트의 IA·핵심 플로우·UI 패턴 수집 — 필요 시 `ia-from-url`·`screen-inventory` 스킬 재사용.
- 사이트별 **서브에이전트 팬아웃**(병렬)으로 동일 체크리스트 적용 → 비교표.
- 비교표 컬럼: `사이트 · IA특징 · 검색/필터 · 전환플로우 · 정보밀도 · 강점 · 약점`.

### 3. 휴리스틱 평가 (객관화)
- **NN/G 10 사용성 휴리스틱** + 접근성(WCAG 핵심) + 모바일 체크리스트로 대상 사이트 점검.
- 각 위반에 **증거(URL/요소/스크린샷)** + 심각도(High/Med/Low) + 영향 사용자/빈도.

### 4. 페인포인트 → 개선 도출
- 페인포인트 표: `# · 영역 · 페인포인트 · 휴리스틱 위반 · 증거 · 심각도`.
- 개선사항 표: `# · 대응 페인포인트 · 개선안 · 벤치마크 근거(어느 경쟁사가 어떻게) · 기대효과 · 우선순위(임팩트×노력)`.
- 우선순위: Impact(高/中/低) × Effort(高/中/低) → Quick-win / Major / Fill-in / 보류.

### 5. 산출 (보고서)
- `projects/<slug>/benchmark/benchmark-report.html`(2단 HTML, 좌: 비교/페인포인트/개선 표 + 도식, 우: 방법론·출처) 또는 `.md`.
- 도식: 경쟁사 포지셔닝, 개선 우선순위 매트릭스(임팩트×노력 4분면, Mermaid/표).
- **출처 목록** 필수(모든 주장 추적 가능).

## 산출물 골격
```
projects/<slug>/benchmark/
└── benchmark-report.html   # 비교표 + 페인포인트·개선 표 + 우선순위 매트릭스 + 출처
```

## 함정
- 주관적 "예쁘다/별로다" 금지 → 휴리스틱·접근성 기준으로 환원.
- 로그인 뒤·결제 등 미접근 영역은 추정 금지, "미확인"으로 표기.
- 경쟁사 장점 맹목 복제 금지 — 대상 컨텍스트(사용자·비즈니스)에 맞는지 판단.
- 페인포인트는 **재현 경로**(어디서 어떻게)와 함께 기록.
