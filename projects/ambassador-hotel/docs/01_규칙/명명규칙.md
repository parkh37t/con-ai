# 명명 규칙 (L0) — 앰배서더 호텔 화면설계

> S2B `규칙.md`의 명명·URL·ID 사상을 이식한 전역 표준. **화면ID·URL은 임의 입력하지 않고 규칙으로 산출**한다.
> 🟡 일부 세그먼트(도메인/영역)는 앰배서더 호텔 RFP 확정 후 채운다.

---

## 1. 포털 세그먼트

| 포털 | 세그먼트 | 파일 프리픽스 | 채번 대역(프로그램ID 예시) |
|------|---------|--------------|--------------------------|
| 프론트(고객) | `front` | `front-` | 1000번대 (`PG_FR1001`) |
| 관리자(운영) | `admin` | `admin-` | 3000번대 (`PG_AD3001`) |

## 2. 화면 ID 규칙

- 패턴: `{prefix}-{영역}-{기능}` (소문자 kebab-case)
  - 예: `front-rooms-detail`, `front-booking-step1`, `admin-reservation-list`
- 접미사 규칙: 팝업 `*Popup` · 탭 `*Tab` · 등록/수정/상세 `Create`/`Update`/`Detail` · 목록 `List` · 단계 `step1·step2`
- 결정된 ID는 각 포털 nav `PATH_MAP`에 등록.
- **3대 키 일치 불변식**: `화면ID = HTML 파일명 = 개발목록 ID`.

## 3. 영역(섹션) 키 — 🟡 RFP 확정 후 확정

> 아래는 호텔 홈페이지 일반 가정. 앰배서더 실제 메뉴체계(IA 산출물 참조)로 교체한다.

| 포털 | 영역 키(가안) |
|------|--------------|
| 프론트 | `home` · `about` · `rooms` · `dining` · `facilities` · `offers` · `booking` · `membership` · `location` · `contact` |
| 관리자 | `dashboard` · `reservation` · `room` · `rate` · `member` · `content` · `promotion` · `report` · `system` |

## 4. URL/Endpoint 규칙 (백엔드 — 옵션, 런타임 앱 전환 시)

- BFF: `/{domain}/{subdomain}/{system}/{package}/{screenID}/{action}`
- API: `/api/{domain}/{area}/{model}/{action}`
- Action 7종 고정: `init`(GET)·`search`(POST)·`find`(GET)·`create`(POST)·`update`(POST)·`delete`(POST)·`process`(POST)
- URI 문자: 영소문자·숫자·하이픈·camelCase Model. 한글·언더바·말미 슬래시 금지.

## 5. ID 자동 채번 사상 (S2B 계승)

- ID는 원천 값 + 순서 기준 자동 계산. 사람이 직접 입력 금지.
- 행 삭제 금지 → `사용여부=N`. 관계는 매핑으로 표현.
