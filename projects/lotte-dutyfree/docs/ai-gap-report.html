롯데면세점 AI 활용 테스트 — SB·TC 생성 갭 분석

benchmark-painpoint AI(Claude/Gemini) 산출물 vs 기획자 작성(정답) · 6과제 · 와일리 OS 시사점

⚠ 분석 방법·한계: 산출물 패키지(SB=PPTX, TC=xlsx/html)의 구조 메타(슬라이드 수·시트/케이스 수)와 핵심 텍스트 기반 비교입니다. 전 슬라이드 정독은 대표 과제(PD-4247) 표본이며, 정성 평가는 양식·분량·상세도 관점의 구조적 진단입니다.

1. 패키지 개요

AI로 스토리보드(SB)·테스트케이스(TC)를 생성하는 PoC. 과제마다 AS-IS 화면 + 요건정의 + 기획자 작성(정답) + AI 산출물이 짝.

2. SB(스토리보드) 생성 비교 — 분량·양식

SB는 PPTX. 같은 요건에 AI와 기획자가 각각 작성. 슬라이드 수 = 상세도·커버리지의 1차 지표.

발견: Claude SB는 단순 변경(PD-4247)엔 비교적 충실하나, 화면·케이스가 많은 과제(PD-4964·4656)에서 2장으로 급격히 빈약해진다(기획자 11~15장). 또 Claude SB가 화면ID(MFPD1)·작성자(기획AI)를 임의 부여 — 롯데 명명규칙·정답 양식과 불일치.

TC는 xlsx/html. 케이스 수·시트 구조 비교. CM-4296은 Claude·Gemini·기획자 3자 비교.

발견: TC 생성에서 AI는 케이스 양산에 강하다(LP25-815 90개). 다만 기획자 정답은 업무/시트 단위 분류 체계를 갖춘 다중시트 구조라, AI의 단일시트 평면 나열과 구조·분류 체계가 다르다. Claude와 Gemini도 산출 형식(표 행수·구성)이 서로 달라 일관 양식 부재.

4. AI 갭 패턴 (4종)

GAP-1 · 표준 양식 미준수High
현상
AI 산출물이 롯데 표준 SB 양식(표지·개정이력·JIRA 메타·번역표·Description·End)을 따르지 않음. TC도 다중시트 분류 체계 대신 평면 나열.
근거
Claude SB(PD-4247)는 변경개요·비교·확인 4섹션 구성 — 기획자 양식과 상이.
GAP-2 · 분량·상세도 빈약(복잡 과제)High
현상
화면·케이스가 많은 과제에서 AI SB가 2장으로 급감(PD-4964·4656). 픽셀 사양·케이스 분기·다국어 상세가 누락.
근거
Claude 2장 vs 기획자 11~15장(0.13~0.18×).
GAP-3 · 메타 임의 부여Med
현상
AI가 화면ID(MFPD1)·작성자(기획AI)를 자체 생성 → 롯데 명명규칙·채번 체계와 충돌(3대 키 불일치).
GAP-4 · 도구 간 일관성 부재Med
현상
Claude·Gemini가 같은 과제(CM-4296)에 서로 다른 형식·케이스 수 산출 → 양식 표준이 없으면 재현·비교 불가.

5. 와일리 OS 해법 매핑

각 갭은 우리 내재화 메커니즘이 직접 해소한다.

갭와일리 OS 해법근거
GAP-1 양식 미준수골든 복제→개조 + 8단 디스크립션 고정07§B·E · screen-spec
GAP-2 분량 빈약SSOT(작업가이드·요건) 충실 로드 + 콘텐츠 5원칙(화면 실재 전수)07§A·F
GAP-3 메타 임의명명규칙 3대 키 일치(화면ID=파일명=개발목록)명명규칙 · CLAUDE §3
GAP-4 일관성 부재html-lint·마커 audit·verify 표준 검증 게이트07§G·H · scripts

핵심: 롯데 AI 실험이 보여준 건 "AI는 내용은 맞히지만 표준 양식·분량·일관성에서 무너진다"는 것. 와일리 OS는 골든 양식 + SSOT + 검증으로 정확히 이 셋을 강제해, AI 산출물을 롯데 표준 SB 양식 그대로 양산 가능하게 한다.

6. 결론 · 실증

  • SB 생성: AI는 변경 요약·리스크 제기에 강하나, 표준 양식·분량·다국어에서 갭(특히 복잡 과제 2장).
  • TC 생성: AI는 케이스 양산에 강하나(90개), 다중시트 분류 체계·도구 간 일관성 부재.
  • 처방: 와일리 OS의 골든·SSOT·검증으로 양식·분량·일관성을 강제 → AI 장점(속도·커버리지) + 표준 준수.

실증: 동일 PD-4247 요건을 와일리 OS로 만든 2단 화면설계서 → front-home-main (AS-IS↔TO-BE 인터랙티브 전환 · 번역표 데이터매핑 · lint·마커 검증 통과). Claude SB의 정적 비교보다 표준·검증이 강함.
