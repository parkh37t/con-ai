# S2B AI 생산 방법론 — 학습 보고서

> **목적**: 롯데면세점(프론트·관리자) 화면설계를 위해 con-ai로 이식하는 **S2B AI 생산 방법론(운영체계)**를 분석·정리한 기준 문서.
> **출처**: S2B 핵심 설계 MD 16종 + AI 방법론 PPTX 11슬라이드 + `s2b-prototype` 공개 산출물 + `s2b-ai-method.html`.
> **작성일**: 2026-06-24

---

## 0. 한 줄 정의

> **S2B 방법론 = AI의 비결정성을 7개 계층(L0~L7)으로 가둬, 다수 기획자의 자연어 요청을 균일 품질의 산출물로 대량 생산하는 "스펙 주도 AI 생산 운영체계(OS)".**

단순히 "AI로 화면을 그리는 기술"이 아니라, **산출물·도메인·검증·데이터·협업·프롬프트를 전부 문서로 코드화**한 생산 라인이다. S2B에서는 이 OS로 약 1,424개 HTML 화면설계서를 생산했다.

핵심 구분: **S2B 산출물은 정적 HTML이며, 앱 런타임에 AI가 도는 게 아니라 "제작 단계"에서만 AI를 쓴다.**

---

## 1. 7계층 아키텍처 (the real "AI 구조")

아래→위로 컨텍스트를 쌓을수록 AI 출력이 고정된다.

```
L7 프롬프트 규율   ┐ 12원칙 + "언급 외 코드 보존" 가드레일
L6 협업 파이프라인  │ 기획자↔AI 오퍼레이터 분업, 폴더 큐(요청→진행중→완료)
L5 자동 검증       │ html-lint 훅(13패턴) + Python audit/verify/patch(~30개) + Playwright
L4 커스텀 스킬     │ ★ "어떻게 만드나"를 코드화한 SKILL.md (골든 복제→개조)
L3 산출물 규격     │ 2단 골든 템플릿 + 더미데이터 사전(고정 캐스트) + 입력필드 정책
L2 요구사항        │ RFP 201 + SFR 444 추적표 (검수 3-state, 결제 14프로세스…)
L1 SSOT 도메인     │ 포털별 작업가이드(권한·E2E·상태·연계이벤트·정책·용어)
L0 전역 규칙       │ 명명·URL·BFF/Process/Program·DDD 4-layer 아키텍처
```

---

## 2. 계층별 상세

### L0 — 전역 규칙 (`규칙.md`)
프런트 명명에 그치지 않고 **백엔드 아키텍처 표준**까지 포함.

- **관리대장 구조**: BFF / Process / Program을 억지 1:1로 묶지 않고 **매핑 시트**로 사용관계 표현. ID는 사람이 입력하지 않고 **규칙으로 자동 채번**.
  - 프로그램ID 채번 대역: 수요 1000번대(`PG_IM1001`) / 공급 2000번대 / 관리 3000번대
- **URL 계산식**:
  - BFF: `/{domain=catalog}/{subdomain}/{system}/{package}/{screenID}/{action}`
  - API: `/api/{domain}/{area}/{model}/{action}`
  - Action 7종 고정: `init·search·find·create·update·delete·process` (REST `PUT/PATCH/DELETE` 폐기)
  - URI 규칙: 영소문자·숫자·하이픈·camelCase Model, 한글·언더바·말미 슬래시 금지
- **DDD 4-layer 강제**: 의존 방향 `interfaces→application→domain`, `infrastructure→domain`.
  - 클래스/패키지 위치까지 규정 (`{Model}CommandService` → `application/commandservice`, MyBatis Mapper → `infrastructure.jdbc`)
  - 강제 규칙: 필드주입(`@Autowired`) 금지·생성자 주입 / 도메인 모델 public setter 금지 / `@Transactional`은 Application만 / `@RequestBody`엔 `@Valid` / 도메인에 JPA 어노테이션 금지(MyBatis 기준)

### L1 — SSOT 도메인 (`{포털}/작업가이드.md`)
**AI를 도메인 전문가로 만드는 단일 출처.** "가장 중요한 입력 컨텍스트"로 명시됨.

작업가이드 1개에 담기는 것:
1. 포털 정의(미션·대상·진입점)
2. 사용자 유형·**권한 매트릭스**
3. 업무 도메인 범위(**책임지는 / 책임지지 않는** 업무 — 포털 경계)
4. 화면 ID 규칙
5. 포털 공통 레이아웃·컴포넌트
6. **End-to-end 업무 흐름** + **핸드오프 지점**
7. **타 포털 연계 이벤트 매트릭스** (`quote.submitted`·`inspection.requested` 등 이벤트명)
8. **상태값 표준** (예: 검수 3-state = 검수요청/검수요청반려/검수합격)
9. 정책 요약(잠금·마감·이력·알림·보관)
10. 도메인 용어집 + 용어 통일표(거래유형→거래구분 315건 등)

→ 정책·용어의 단일 출처가 **AI 환각·불일치를 억제**한다.

### L2 — 요구사항 (`03_기능_요구사항_정리.md`)
- RFP 201개(ECR/ACR/SFR/PER/INR/DAR/TER/SER/QUR/COR/PMR/PSR) + **SFR 444개** 분류·추적표
- 회의 결론을 룰로 박제: **검수정책(260512) A~J**(상태 8→3, 15일 자동합격), **결제·정산 14프로세스 SSOT**("돈 냈으면 환불, 안 냈으면 면제")

### L3 — 산출물 규격 (골든 템플릿 + 더미데이터 사전 + 입력필드 정책)
- **2단 골든 템플릿**: `좌(실제 화면) + 우(디스크립션=사양서)`, **번호 마커(num-badge)로 1:1 미러링**.
  - 좌 `①` ↔ 우 사양서 `①` 1:1 대응 → 화면=사양서가 절대 어긋나지 않음
  - 우측 디스크립션 **8단 고정 골격**: 화면ID → info-table 3행 → CASE 전환 → proc-table → policy-box → 데이터 매핑 → spec-header/field → **msg-tbl(맨 아래)**
  - `setCase(group,value)` 케이스 스위처: 한 정적 HTML로 거래유형·인증상태·검증·파일유무 등 다양한 상태 시연
- **더미데이터 사전 = 데모용 환각 차단기**:
  - **고정 캐스트 원칙** — 모든 화면이 같은 가공 데이터 사용(공급사 `(주)에스투비종합설비/김공급`, 수요기관 `부산가상중학교/홍길동`, 기준일 `2026-02-07`). "홍길동2·테스트업체" 즉흥 생성 **금지**.
- **입력필드 정책**: 타입별 byte 제한·허용문자·자동포맷·유효성 노출시점(포커스아웃 + 저장 시 2단계)·에러 표시 규격.

### L4 — 커스텀 스킬 (`SKILL.md`) ★ 메커니즘의 핵심
실제 프로덕션 Claude Code 스킬. 구성:
- YAML frontmatter(name/description)에 **트리거 문구**("마커 맞춰","새 페이지 만들"…) → 자동 발동
- **골든 복제→개조** 절차(백지 생성 금지 — 셸·마커·디스크립션 골격이 한 번에 따라옴)
- 2단 셸 **불변식**(GNB·LNB·브레드크럼은 `screen-wrap` 안 / `right-panel`은 형제)
- 마커 부여 5기법, 회귀 13패턴, **~30개 Python 스크립트 인벤토리**, 흔한 실패패턴, **메모리 학습 누적**(`feedback_*`·`project_*`)

### L5 — 자동 검증 (3중 체계)
| 단계 | 시점 | 도구 | 대상 |
|------|------|------|------|
| 1차 | 저장 즉시 | `html-lint.ps1` (PostToolUse 훅) | 13개 회귀 패턴 |
| 2차 | 단일 화면 | Playwright + 로컬 서버 | 셸 구조·콘솔 에러 |
| 3차 | 전체 일제 | `verify_all_pages.py`(1,424 전수)·`audit_mirror_lr.py`(좌↔우 미러) | 마커 정합 |

- **stale 뷰 주의**: `file://` 금지, `python -m http.server` + 강력 새로고침(Ctrl+Shift+R)으로만 검증.

### L6 — 협업 파이프라인
- **분업**: 기획자(프롬프트 작성) ↔ AI 오퍼레이터(Claude Code 실행) ↔ PM/리드(일정·컨펌)
- **폴더 큐**: `수정요청업로드 → 진행중 → 완료` 로 요청 직렬화
- **파일 명명**: `{업무}_{화면ID}_{화면명}_{수정|요청}_{날짜}_{작성자}.txt`
- **컨펌 3대 키 일치**: `화면ID = HTML 파일명 = 개발목록 ID`

### L7 — 프롬프트 규율 (12원칙)
1. 화면ID/URL로 대상 고정(토큰 절약) 2. "어디를·어떻게" 명확화 3. 요소 단위 타게팅 4. (추가)/(삭제)/(유지) diff 5. **가드레일: 언급 외 코드 보존·저장** 6. 디자인시스템 클래스만 7. 참조 화면 활용 8. 복제 후 치환 9. 캡쳐 이미지 참조 10. 페이지↔팝업 변환 11. 동작·검증 자연어 명세 12. 구조적 스펙-as-프롬프트

> ★ 가장 자주 등장한 핵심 문장:
> **"위에서 언급한 수정 사항 외의 기존 코드는 절대 삭제·이동하지 말고 수정 완료 후 저장해줘."**

## 3. 규모 / 성과

| 항목 | 수치 |
|------|------|
| 포털 | 3개(수요·공급·관리) + 공통 |
| 화면 HTML | ~1,424개 |
| 기능 요구사항(SFR) | 444개 |
| 분석 .md 문서 | 108개 |
| 협업 대화(KakaoTalk) | 66,572줄 |

**성공 요인**: 산출물 규격 코드화 · SSOT 계층화 · 골든 복제→개조 · 훅+스크립트 자동 검증.
**리스크**: stale 뷰(로컬서버) · 코드 훼손(가드레일 필수) · 정합 붕괴(ID=파일명=개발목록).

## 4. 롯데면세점(con-ai) 이식 전략 — 전이 vs 폐기

목표: **S2B의 7계층 OS를 골격으로 이식**, 도메인은 롯데면세점(프론트+관리자)으로 교체.

| 계층 | 전이(재사용) | 폐기(S2B 전용) |
|------|:---:|:---:|
| L0 규칙·아키텍처 | ✅ 명명·레이어·ID 자동채번 **사상** | ❌ catalog/goods URL, S2B BFF |
| L1 SSOT 작업가이드 | ✅ **틀**(권한·E2E·상태·연계·용어) | ❌ 조달 도메인 내용 |
| L2 요구사항 추적 | ✅ RFP/SFR 추적표 **구조** | ❌ 444개 조달 요구사항 |
| L3 산출물 규격 | ✅ 골든 템플릿·더미사전·입력정책 **방식** | ❌ S2B 거래 케이스 |
| L4 커스텀 스킬 | ✅ 스킬 **작성법 자체** | ❌ admin-shell 정합 로직 |
| L5 자동 검증 | ✅ 훅+audit/verify/patch **3중 체계** | ❌ S2B 전용 패턴 |
| L6 협업 파이프라인 | ✅ 그대로 | — |
| L7 프롬프트 규율 | ✅ 그대로 | — |

→ **L1/L2/L3의 도메인 콘텐츠는 롯데면세점 PPTX(스펙) 도착 시 채운다.** 그 전까지는 스켈레톤 + TODO로 유지.
