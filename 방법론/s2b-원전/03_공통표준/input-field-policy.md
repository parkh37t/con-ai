## 2. 입력 가능 범위 정책

- 필드별 **byte 기준**으로 입력 제한 적용
- 입력 가능 문자 유형은 필드별로 강제 제한
- 별도 정의 시 해당 화면에서 별도 명시 필요

---

## 3. 유효성 체크 (Validation) 정책

### 3.1 Fail Type

| 타입 | 설명 |
|------|------|
| **TYPE-A** | 필드 하단에 에러 메시지 노출 — 입력 필드 바로 아래 표시 |
| **TYPE-B** | 동일 구조이나 스타일/위치 정책 다를 수 있음 — 에러 메시지 별도 영역 표시 가능 |

### 3.2 에러 메시지 표시

- `$error_message$` 형태로 출력
- Placeholder와 별도로 노출

---

## 4. 유효성 체크 노출 시점

| NO | CASE | 설명 |
|----|------|------|
| 1 | 필드 포커스 아웃 시 | 입력 완료 후 벗어나면 검증 |
| 2 | 등록 버튼 클릭 시 | 전체 필드 일괄 검증 |

---

## 5. 공통 입력 UX 정책

### 자동 포맷팅

| 유형 | 포맷팅 |
|------|--------|
| 전화번호 | 하이픈(-) 자동 삽입 |
| 금액 | 콤마(,) 자동 삽입 |
| 날짜/시간 | 구분자 자동 삽입 |

### 입력 제한

- 허용 문자 외 입력 **실시간 차단**

### 스크롤 정책

| 유형 | 스크롤 |
|------|--------|
| 일반 입력 | 없음 |
| textarea | 세로 스크롤만 허용 |

---

## 6. 예외 / 주의사항

- 입력 가능 범위는 화면별 별도 정의 가능
- 특수문자는 필드별 허용 범위 다름
- 숫자 필드는 문자 입력 불가
- 날짜/시간은 반드시 포맷 유지

---

## 7. 핵심 요약

| 항목 | 내용 |
|------|------|
| 입력 제한 기준 | 모든 필드 byte 기준 |
| 허용 문자 | 입력 타입별 엄격 분리 |
| 자동 포맷팅 | 필수 적용 |
| 유효성 체크 | 포커스 아웃 + 저장 시 2단계 수행 |
| 에러 메시지 | 필드 단위 노출 |
