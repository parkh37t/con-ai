## B. 우리(와일리)가 능가한 지점 — s2b2에 없던 것

1. **메시지·알림 정의표(msg-tbl)** — s2b2는 예외 문구가 디스크립션에 흩어짐. 우리는 **유형(확인/경고/안내)·메시지·발생조건을 별도 표로 한눈에**. 개발 이관 시 누락 0.
2. **sourceId 그라운딩** — 모든 메시지·필드에 `slide40#1` 같은 **원본 추적 id**. 사양의 출처가 PPTX 어디인지 검증 가능(s2b2엔 부재).
3. **ScreenSpec 정규 JSON 경유** — 화면이 자유 생성물이 아니라 `examples/BO006.screenspec.json`에서 결정론적으로 파생. 마커 1:1이 코드로 보장.
4. **검증 자동화 일체** — `html-lint`(회귀 13패턴) + `verify_all_pages`(좌우 영역 마커) + `audit_mirror_lr`(필드 라벨 set) 전수 통과를 출고 기준으로.
5. **신세계사이먼 브랜드 토큰** — primary를 사이먼 레드(#be123c)로, 도메인 정체성 반영.

> 요약: **s2b2의 깊이(6속성·API·정책·REQ) + 와일리의 검증가능성(msg-tbl·sourceId·ScreenSpec·lint)**.

## D. 남은 격차(따라잡을 것)
- s2b2는 GNB/LNB/브레드크럼을 **JS 자동 렌더**(`sup-nav.js`) → 1,428화면 일관성. 우리는 현재 정적. → 차후 BO 네비 JS화.
- s2b2 요구사항 **자동매칭 점수(score)** → 요구사항 추적표 연동 시 도입.
- 규모(1,428) 대비 우리는 2화면. → ScreenSpec 자동화로 양산 경로 확보가 다음 과제.
