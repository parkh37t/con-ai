# 09 — 세션 회고: 와일리 OS는 어떤 AI 방법론인가

> **이 문서의 목적**: 워크벤치가 실제 세션에서 무엇을 했고, 그 산출물이 **어떤 과정과 어떤 인사이트의 AI 방법론**인지 회고·종합한 자산.
> 5개 관점(과정·원리·AI 인사이트·거버넌스·메타)을 병렬 분석해 통합했다. 다음 세션이 "우리가 무엇을 하는 시스템인가"를 1문서로 계승하기 위한 기록.
> 근거: `00_OVERVIEW`~`08_agent-team`, `CLAUDE.md`, `.claude/{skills,hooks,agents}`, `scripts/`, 롯데 `ai-gap-report.html`·`pd4247-comparison.html`·`롯데SB양식_매핑.md`.

## 1. 한 문장 정의

**"어떤 기획 입력(PPTX·PDF·HTML·Figma)이든 하나의 정규 스펙(ScreenSpec JSON)으로 수렴시켜, 골든 템플릿 복제·개조로 2단 HTML 화면설계서(SSOT)를 양산하고, 실행되는 코드 게이트로 검증해 출고하는 결정론적 AI 생산 파이프라인."**
→ 화면 몇 장이 아니라 **화면설계를 양산하는 생산 시스템 자체**다.

## 2. 과정(파이프라인) — 세션이 실제로 밟은 경로

6단계는 `[입력]→[추출]→[정규화(ScreenSpec)]→[생산(골든 복제·개조)]→[검증(lint·미러)]→[배포]`로 고정된다(`00_OVERVIEW §1`).
핵심 설계 = **어댑터(라우터) + 불변 코어(생산·검증)의 분리**. 입력이 제각각이어도 라우터만 갈아끼우면 생산부는 입력 종류와 무관해진다(`00_OVERVIEW §2`).

세 프로젝트가 파이프라인의 **서로 다른 구간**을 밟았다:

| 프로젝트 | 밟은 구간 | 증거 |
|---|---|---|
| **신세계사이먼 BO** | 전 구간 최초 완주(입력→추출→ScreenSpec→생산→검증) | PPTX 67p → BO006·BO316·BO007, `examples/BO006.screenspec.json`(모든 필드에 `sourceId`) |
| **롯데 PD-4247** | 생산·검증 + **골든 역류(reverse-flow)** | GAP-1 발견 → 양식 매핑 → `lotte-sb-golden.html` 등록 → `front-home-main` 리빌드(lint 0·audit 0·verify 0·미러 0) |
| **앰배서더 호텔** | 0단(인테이크) + 본류 **입력 대기(pending)** | IA·화면본수·벤치마킹 → `00_입력원본` RFP 투입소 + 7계층 골격 승격 |

세션 전반은 화면 생산을 넘어 **파이프라인 인프라 구축**이라는 메타 작업이었다: OS 문서 00~08, 인테이크 스킬 3종, S2B 생산 메커니즘 내재화(07), 마커 audit/patch 도구, 6종 wylie 에이전트.

## 3. 방법론을 지탱하는 원리 (왜 존재하나 — LLM 실패모드 봉쇄)

"AI에게 잘 부탁하는 규칙"이 아니라, LLM 3대 실패모드(**환각·드리프트·비재현성**)를 각각 겨냥해 훅·audit·골든으로 **코드화한 강제 장치**다(`04_knowhow §A·B`).

1. **SSOT = 2단 HTML 고정** — 정본이 도구·세션에 분산되는 **드리프트 차단**. Figma·Express·Canva는 렌더 타깃일 뿐.
2. **골든 복제→개조, 백지 금지** — 셸·8단 골격 재생성 시 생기는 **구조 환각 차단**. 불변식(GNB·LNB는 `screen-wrap` 안, `right-panel`은 형제)이 복제로 자동 보존.
3. **ScreenSpec strict 스키마 + `sourceId`/`dummyRef` 그라운딩** — 추적 id 없는 필드·더미 **환각 차단**("그라운딩 없으면 폐기"). 단 문법 보장 ≠ 의미 정확 → 행×열 사후 대조 별도.
4. **마커 1:1 미러(좌 num-badge == 우 spec)** — 한 JSON에서 코드로 함께 렌더 → **분량 빈약·비재현성 차단**. `audit_mirror_lr.py`가 좌우 배지 diff.
5. **검증을 모델이 아니라 하네스에** — "앞으로 항상 X는 메모리가 아니라 훅"(`04_knowhow §C`). `html-lint.py`가 Write/Edit 직후 회귀 13패턴 자동 스캔, `audit_markers`·`verify_all_pages`·`patch_markers`가 전수 검사·자동정정.
6. **3대 키 일치(화면ID=파일명=개발목록)** — 기획·설계·개발이 다른 화면을 가리키는 추적 단절 차단.

## 4. 핵심 AI 인사이트 — "AI를 이긴 게 아니라 표준 위에 올렸다"

롯데 AI 테스트 6과제가 방향을 정했다. **AI는 요건의 '내용'은 정확히 맞히지만 표준 '양식'에서 무너진다.**
Claude/Gemini는 PD-4247의 3개 변경값(폰트 15→14·비활성 #888→#000·여백 10→5)을 모두 맞히고 스와이프 리스크까지 능동 제기 — 요건 이해는 인간 기획자와 **동률(○=○)**.
무너지는 지점은 재현 가능한 4개 갭으로 계량된다:

| 갭 | 현상(계량) | 처방(1:1) |
|---|---|---|
| **GAP-1** 양식 미준수 | 표지·개정이력·번역표·End 누락 | 골든 복제→개조 + 8단 고정 |
| **GAP-2** 분량 빈약 | Claude 2장 vs 기획자 11~15장(0.13~0.18×) | SSOT 로드 + 마커 전수 |
| **GAP-3** 메타 임의 | 화면ID `MFPD1`·작성자 `기획AI` 자체 생성 | 3대 키 일치 |
| **GAP-4** 도구 간 불일치 | Claude·Gemini가 같은 요건에 다른 형식 | lint·audit·verify 게이트 |

→ 설계 초점은 "**더 똑똑한 프롬프트**"가 아니라 "**형식을 강제하는 외부 골격**". PD-4247 대조 화면은 이를 과장 없이 실증한다 — 요건 정확도는 동률로 인정하고, **양식·메타·인터랙티브·마커·다국어·자동검증 6개 축에서만** OS 우위를 주장.
**결론 문구: "우리가 AI를 이겼다가 아니라, AI를 표준 위에 올렸다."**

## 5. 메타 교훈 — 자기개선 루프·재현성·자산화

- **자기개선 폐루프가 롯데에서 1회전 완주**: `갭 발견 → 해법 매핑 → 골든 등록 → 실증 리빌드 → 프로젝트 확산`. 검증 실패(GAP)가 **골든 개선으로 환류**돼 다음 화면부터 재발하지 않음(개별 교정이 아니라 표준 자산화).
- **재현성은 사람 규율이 아니라 하네스로 강제**: 백지 금지(출발점 고정) + PostToolUse 훅(회귀 즉시 검출) + 전수 audit/patch. "누가·어떤 AI가 만들어도 같은 표준."
- **대화가 재사용 자산으로 응고**: 사실=CLAUDE.md, 절차=스킬, 강제=훅, 역할=에이전트로 계층 분리(`00_OVERVIEW §3`). 와일리-OS 폴더의 점진 성장(00~04 환경 → 05 벤치마크 → 06 도식화 → 07 원전 내재화 → 08 에이전트 → **09 회고**)이 세션을 넘어 축적되는 방법론 메모리의 물증.
- **역할 침범도 코드로 막음**: 6종 에이전트를 frontmatter `tools` 화이트리스트로 물리 분리 — intake/verify는 읽기·검사만, screen만 생산, diagram은 Edit만, render는 변환·배포. "검증은 항상 verify로 수렴, 통과가 출고 조건."

> **정직한 한계**: 지금 정합·검증이 보장하는 건 **구조·양식·메타**이며, 도메인 실값(번역 실값·면세 규정·호텔 요금)은 아직 **가안(🟡)** — PPTX/RFP 확정 후 채울 구간으로, 대조 화면에 스스로 명시해 뒀다.

## 6. 한 줄 결론

> AI 화면설계 양산의 진짜 레버리지는 화면을 잘 그리는 것이 아니라, **입력 다양성을 라우터로 흡수해 단일 정규 스펙으로 수렴시키고, 골든 복제·개조로 백지 창작을 배제하며, 검증을 출고 조건인 내장 코드 게이트로 박아 — 실패를 방법론 강화 입력으로 삼는 자기개선 폐루프를 코드 아티팩트(골든·훅·스킬·에이전트)로 닫아, 다음 세션과 다른 AI가 그 자산을 무료로 계승하게 만드는 것**이다.
