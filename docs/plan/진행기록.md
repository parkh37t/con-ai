## AS-IS 분석 (4단계 프로세스 ①) — 2026-09-05

**완료한 기능**
- URL 입력 → Playwright 로 방문 → 데스크톱·모바일 스크린샷 + 페이지 구조 추출(제목·헤딩·내비·폼/필드·버튼·counts) → 모델 어댑터가 페인포인트 초안 작성 → 기획자가 채택/거부
- 어댑터 `draftPainPoints`: anthropic(구조화 출력) / fixture(규칙 기반 결정적 — 레이블 없는 필드, alt 없는 이미지, h1 없음·중복, 내비 과다, 모호한 버튼 문구, caption 없는 표, iframe, meta description 없음)
- 실패는 코드와 함께 failed 로 기록(navigation / browser / draft / internal). 성공으로 위장하지 않음
- 자체 데모 대상 `/asis-sample`(합성 레거시 페이지, 의도된 페인포인트 포함) 제공 — 외부 네트워크 없이 시연·검증 가능
- 웹: `#/asis` 목록·실행, `#/asis/:id` 상세(스크린샷 토글, 구조 요약, 요약, 페인포인트 표와 채택/거부)

**실행 방법**: `pnpm dev` 후 웹의 "AS-IS 분석" → 데모 대상 채우기 → 실행

**검증 결과**
- `pnpm check`: typecheck 통과, 테스트 415개 통과 (AS-IS 백엔드 11 + 웹 13 추가)
- `pnpm e2e`: 2 passed — AS-IS(실행 → succeeded → 스크린샷 로드 → 구조 → 페인포인트 8건 → 채택 반영)와 기존 세로 조각 모두 통과
- 고친 것: tsx(esbuild keepNames)가 `page.evaluate` 콜백에 주입하는 `__name` 헬퍼가 브라우저에 없어 실패하던 문제 — 문자열 evaluate 로 항등 함수를 먼저 심어 해결

**남은 제한**
- 이 개발 컨테이너는 외부 egress 가 프록시에 막혀 외부 URL 이 failed(navigation) 가 될 수 있다. 사용자 PC 에서는 제약 없음
- 로그인 전 단계라 분석은 서버 기본 어댑터로 실행된다(사용자별 자격 증명은 ADR 0014 의 1단계에서 연결)
- 페인포인트는 구조 신호 기반 초안이다. 실제 사용 흐름·업무 맥락 페인포인트는 기획자가 보완해야 한다
- To-Be IA·요구사항으로의 연결(채택한 페인포인트 → 요구사항 초안)은 다음 단계

## 운영 배포 준비 · SSRF 차단 — 2026-09-05

**완료한 기능**
- 한 포트 운영 모드: API 가 웹 빌드(`WEB_DIST`)를 함께 제공하고 SPA 폴백·캐시 정책을 적용한다. `GET /healthz`, `HOST` 지원, 인증 없음 경고 로그
- 컨테이너 배포: `Dockerfile`(node:22-bookworm + Playwright chromium), `docker-compose.yml`(볼륨 `./var/data`), `.dockerignore`, `render.yaml`(Render 청사진)
- AS-IS 분석 SSRF 차단: 입력 URL·리다이렉트·하위 리소스의 해석된 IP 를 검사해 사설·루프백·링크로컬(169.254.169.254 포함)·CGNAT·문서용·멀티캐스트·예약 대역과 IPv6 ULA 를 차단. IPv4-mapped IPv6 는 풀어서 재검사, IP 판독 실패·DNS 실패는 차단(fail closed)
- 탈출구: `ASIS_ALLOW_PRIVATE`, `ASIS_ALLOWED_HOSTS`, `ASIS_BLOCKED_HOSTS`. 데모 대상은 자기 서버의 `/asis-sample` 경로일 때만 허용(포트까지 확인해 루프백 포트 스캔 차단)
- 실패 코드 `blocked` 추가(웹 라벨 "정책 차단 (사설·내부 주소)"), 차단된 하위 리소스 수는 `blocked_requests` 로 기록

**실행 방법**: `pnpm serve` (8787 한 포트) / `docker compose up -d --build` / Render 는 저장소를 Blueprint 로 연결

**검증 결과**
- `pnpm check`: typecheck 통과, 테스트 577개 통과
- `pnpm e2e`: 2 passed
- 한 포트 실행을 Playwright 로 15항목 확인(홈·화면 3개·검토 iframe·healthz·폴백·콘솔 오류 0)

**남은 제한**
- **인증 없음**. Render 같은 공개 주소에 올리면 누구나 사용하고 모델 비용이 발생한다. 테스트 후 반드시 접근 제어를 붙인다(ADR 0014 1단계)
- Docker 이미지 빌드는 이 개발 환경에 데몬이 없어 미검증. 배포 장비에서 최초 1회 확인 필요
- SSRF: DNS 리바인딩은 완전히 막지 못한다(우리 해석과 브라우저 해석이 별개). 리다이렉트 중간 단계는 탐지 후 캡처를 중단하지만 이미 나간 요청 1회는 취소할 수 없다. 확실히 막으려면 컨테이너 egress 를 프록시로 제한한다
- 실제 모델 호출은 아직 미검증(자격 증명 없음)

## 브라우저 실행 모드 — 2026-09-05

**완료한 기능**
- 배포된 정적 주소에서 사용자가 자기 자격 증명(API 키 또는 토큰)을 넣으면 **브라우저가 직접 Anthropic API 를 호출**해 화면을 생성한다. 서버 없음
- 파이프라인은 서버와 같은 단계 이름으로 진행한다: 문맥 구성 → 명세 생성 → 스키마·참조 검사 → 렌더 → V1·V2 검증 → 저장
- 자격 증명은 기본 sessionStorage(탭 종료 시 삭제), 선택 시 localStorage. 화면에는 종류와 끝 4자리만. 콘솔·오류 메시지·저장 데이터·내보내기 파일에 값이 들어가지 않는 것을 테스트로 고정
- 생성 결과는 검토·코멘트·수정 흐름을 그대로 타고, 내보내기는 파일 다운로드로 대체(manifest 에 `mode:"browser"`, `approved:false`)
- `validators/result.ts` 가 `node:crypto` 대신 전역 crypto 를 써서 서버·브라우저 양쪽에서 동작

**근거**: Anthropic API 프리플라이트가 `access-control-allow-origin: *` 와 `anthropic-dangerous-direct-browser-access` 를 허용함을 확인(2026-09-05).

**검증 결과**
- `pnpm check`: typecheck 통과, 테스트 640개 통과(브라우저 모드 61개 추가)
- `pnpm e2e`: 2 passed
- 데모 빌드를 `/con-ai/` 로 서빙해 Playwright 확인: 자격 증명 입력 → 배지 변경 → 생성 단계 진행 → succeeded → 새 revision 검토 화면 표시 → V3 not_run → 새로고침 후 유지 → 내보내기 6파일. 콘솔 오류 0
- 서버 모드(`pnpm serve`)에 영향 없음(브라우저 모드 코드는 일반 빌드에 포함되지 않음)

**남은 제한**
- **실제 모델 호출은 미검증**. 이 컨테이너는 브라우저 외부 접속이 막혀 모든 테스트가 fetch 주입이다. 실제 응답의 구조화 출력 수용 여부는 사용자 브라우저에서 처음 확인된다
- V3 실행 검사는 브라우저에서 불가하므로 `not_run`. 따라서 **완료(v1.0) 승인은 거부된다**(필수 검사 미실행). 정식 승인은 서버 실행에서만 가능하며, 브라우저에서는 미승인 상태로 파일을 내려받을 수 있다
- AS-IS 새 URL 분석 불가(다른 사이트를 캡처할 수 없다). 스냅샷의 기존 분석 결과만 보인다
- 여러 사람 공유 불가(브라우저별 저장). 더미데이터가 없는 화면은 빈 표로 렌더되고 unresolved 에 기록된다
- 모델 출력 JSON Schema 는 `packages/model-adapter/src/wire-schema.ts` 를 손으로 옮긴 것이라 한쪽을 고치면 같이 고쳐야 한다
