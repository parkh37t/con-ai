## 세로 조각 v0 — 2026-09-05

**완료한 기능**
- 샘플 프로젝트 시드(와일리 컨버전스 파트너 견적 포털, 가상): 요구사항 5·수용조건, To-Be IA, 화면 3, 레퍼런스 포트폴리오 3(S2B 학습 규격 적용 골든 예시), 더미데이터, 프롬프트 템플릿 v1
- 생성: 프롬프트 템플릿 v1(설계 §8 7구역·내부 계약), 모델 어댑터 anthropic(API 키 / 토큰 두 방식, `messages.parse` 구조화 출력) · fixture(더미, 결정적), 6단계 파이프라인(문맥 → 명세 → 스키마·참조 검사 → 렌더 → 검증 → 저장), 순차 큐, 취소·실패 기록
- 렌더러: ScreenSpec → 오프라인 HTML 목업 + 우측 설명 8절(번호 단일 원본), CASE 전환·더미 검색·정렬·팝업·다운로드, postMessage
- 검증: V1 명세 / V2 렌더 구조 / V3 실행(Playwright), 4상태, 필수 검사 13개
- 검토: 격리 iframe, CASE·기기 전환, 요소·설명 클릭 코멘트(역할·차단), 검증 결과 표, 재검증
- 수정: 코멘트 → AI 수정 프롬프트 초안 또는 직접 입력 → 단건 수정 → 새 revision, 코멘트 해결
- 완료: 승인 게이트(필수 검사 pass·hash·revision·차단 코멘트 0·V6 기록) → v1.0 → `exports/<프로젝트>/<화면>/v1.0/` 6파일 + manifest(design_handoff)
- 세팅: `pnpm bootstrap`, Claude Code SessionStart 훅, `.env.example`

**실행 방법**
```bash
pnpm bootstrap                 # 최초 1회
set -a; source .env; set +a
pnpm dev                       # 웹 5173, API 8787
pnpm check                     # typecheck + 단위·통합 테스트
pnpm e2e                       # 브라우저 e2e (fixture 어댑터)
```

**검증 결과**
- `pnpm check`: typecheck 통과, 테스트 382개 통과 (schemas 68, domain 38, fixtures 51, importers 10, prompt-templates 11, model-adapter 39, renderer+validators 60, worker 19, api 19, web 67)
- API 통합 스모크(실제 renderer·validators·fixture 어댑터): 생성 succeeded(검사 13개 pass, review_ready) → 코멘트 → AI 수정 프롬프트 → 단건 수정(코멘트 resolved) → 승인 200 → 내보내기 6파일 → `/exports/.../manifest.json` 200
- 브라우저 e2e(`pnpm e2e`, fixture 어댑터, 이미지 Chromium): 홈 → 포트폴리오 → 생성(프롬프트 미리보기·실행·새로고침 후 상태 유지) → 검토(격리 iframe, CASE·기기 전환, 요소 클릭 코멘트, V1·V2·V3 pass) → AI 수정 프롬프트·단건 수정(revision 2, 코멘트 resolved) → 완료 v1.0(내보내기 6파일·manifest·`/exports/.../index.html` 200) → 재승인 거부 — 1 passed (12.8s)

**남은 제한**
- anthropic 어댑터는 이 환경에 키·토큰이 없어 가짜 fetch 로만 검증(U-009). 실제 호출 시 구조화 출력 스키마 수용 여부를 확인해야 한다.
- V0·V4·V5·V7 미구현. V3 는 정렬·팝업·페이지 이동을 직접 검사하지 않는다.
- 승인은 화면당 v1.0 한 번. 권한·인증 없음(승인자는 문자열). 큐는 단일 프로세스, 재시도 없음.
- AS-IS 분석(①) 미착수. XLSX 요구사항 수입, 매핑 작업대, 커버리지 화면은 다음 단계.
- 검토 데이터(고객 원문) 커밋 여부 미결(U-006).
