## AS-IS 분석 (4단계 프로세스 ①) — 2026-09-05

**완료한 기능**
- URL 입력 → Playwright 로 방문 → 데스크톱·모바일 스크린샷 + 페이지 구조 추출(제목·헤딩·내비·폼/필드·버튼·counts) → 모델 어댑터가 페인포인트 초안 작성 → 기획자가 채택/거부
- 어댑터 `draftPainPoints`: anthropic(구조화 출력) / fixture(규칙 기반 결정적 — 레이블 없는 필드, alt 없는 이미지, h1 없음·중복, 내비 과다, 모호한 버튼 문구, caption 없는 표, iframe, meta description 없음)
- 실패는 코드와 함께 failed 로 기록(navigation / browser / draft / internal). 성공으로 위장하지 않음
- 자체 데모 대상 `/asis-sample`(합성 레거시 페이지, 의도된 페인포인트 포함) 제공 — 외부 네트워크 없이 시연·검증 가능
- 웹: `#/asis` 목록·실행, `#/asis/:id` 상세(스크린샷 토글, 구조 요약, 요약, 페인포인트 표와 채택/거부)

**실행 방법**: `pnpm dev` 후 웹의 "AS-IS 분석" → 데모 대상 채우기 → 실행

**검증 결과**
- `pnpm check`: typecheck 통과, 테스트 415개 통과 (AS-IS 백엔드 11 + 웹 13 추가)
- `pnpm e2e`: 2 passed — AS-IS(실행 → succeeded → 스크린샷 로드 → 구조 → 페인포인트 8건 → 채택 반영)와 기존 세로 조각 모두 통과
- 고친 것: tsx(esbuild keepNames)가 `page.evaluate` 콜백에 주입하는 `__name` 헬퍼가 브라우저에 없어 실패하던 문제 — 문자열 evaluate 로 항등 함수를 먼저 심어 해결

**남은 제한**
- 이 개발 컨테이너는 외부 egress 가 프록시에 막혀 외부 URL 이 failed(navigation) 가 될 수 있다. 사용자 PC 에서는 제약 없음
- 로그인 전 단계라 분석은 서버 기본 어댑터로 실행된다(사용자별 자격 증명은 ADR 0014 의 1단계에서 연결)
- 페인포인트는 구조 신호 기반 초안이다. 실제 사용 흐름·업무 맥락 페인포인트는 기획자가 보완해야 한다
- To-Be IA·요구사항으로의 연결(채택한 페인포인트 → 요구사항 초안)은 다음 단계

## 운영 배포 준비 · SSRF 차단 — 2026-09-05

**완료한 기능**
- 한 포트 운영 모드: API 가 웹 빌드(`WEB_DIST`)를 함께 제공하고 SPA 폴백·캐시 정책을 적용한다. `GET /healthz`, `HOST` 지원, 인증 없음 경고 로그
- 컨테이너 배포: `Dockerfile`(node:22-bookworm + Playwright chromium), `docker-compose.yml`(볼륨 `./var/data`), `.dockerignore`, `render.yaml`(Render 청사진)
- AS-IS 분석 SSRF 차단: 입력 URL·리다이렉트·하위 리소스의 해석된 IP 를 검사해 사설·루프백·링크로컬(169.254.169.254 포함)·CGNAT·문서용·멀티캐스트·예약 대역과 IPv6 ULA 를 차단. IPv4-mapped IPv6 는 풀어서 재검사, IP 판독 실패·DNS 실패는 차단(fail closed)
- 탈출구: `ASIS_ALLOW_PRIVATE`, `ASIS_ALLOWED_HOSTS`, `ASIS_BLOCKED_HOSTS`. 데모 대상은 자기 서버의 `/asis-sample` 경로일 때만 허용(포트까지 확인해 루프백 포트 스캔 차단)
- 실패 코드 `blocked` 추가(웹 라벨 "정책 차단 (사설·내부 주소)"), 차단된 하위 리소스 수는 `blocked_requests` 로 기록

**실행 방법**: `pnpm serve` (8787 한 포트) / `docker compose up -d --build` / Render 는 저장소를 Blueprint 로 연결

**검증 결과**
- `pnpm check`: typecheck 통과, 테스트 577개 통과
- `pnpm e2e`: 2 passed
- 한 포트 실행을 Playwright 로 15항목 확인(홈·화면 3개·검토 iframe·healthz·폴백·콘솔 오류 0)

**남은 제한**
- **인증 없음**. Render 같은 공개 주소에 올리면 누구나 사용하고 모델 비용이 발생한다. 테스트 후 반드시 접근 제어를 붙인다(ADR 0014 1단계)
- Docker 이미지 빌드는 이 개발 환경에 데몬이 없어 미검증. 배포 장비에서 최초 1회 확인 필요
- SSRF: DNS 리바인딩은 완전히 막지 못한다(우리 해석과 브라우저 해석이 별개). 리다이렉트 중간 단계는 탐지 후 캡처를 중단하지만 이미 나간 요청 1회는 취소할 수 없다. 확실히 막으려면 컨테이너 egress 를 프록시로 제한한다
- 실제 모델 호출은 아직 미검증(자격 증명 없음)

## 브라우저 실행 모드 — 2026-09-05

**완료한 기능**
- 배포된 정적 주소에서 사용자가 자기 자격 증명(API 키 또는 토큰)을 넣으면 **브라우저가 직접 Anthropic API 를 호출**해 화면을 생성한다. 서버 없음
- 파이프라인은 서버와 같은 단계 이름으로 진행한다: 문맥 구성 → 명세 생성 → 스키마·참조 검사 → 렌더 → V1·V2 검증 → 저장
- 자격 증명은 기본 sessionStorage(탭 종료 시 삭제), 선택 시 localStorage. 화면에는 종류와 끝 4자리만. 콘솔·오류 메시지·저장 데이터·내보내기 파일에 값이 들어가지 않는 것을 테스트로 고정
- 생성 결과는 검토·코멘트·수정 흐름을 그대로 타고, 내보내기는 파일 다운로드로 대체(manifest 에 `mode:"browser"`, `approved:false`)
- `validators/result.ts` 가 `node:crypto` 대신 전역 crypto 를 써서 서버·브라우저 양쪽에서 동작

**근거**: Anthropic API 프리플라이트가 `access-control-allow-origin: *` 와 `anthropic-dangerous-direct-browser-access` 를 허용함을 확인(2026-09-05).

**검증 결과**
- `pnpm check`: typecheck 통과, 테스트 640개 통과(브라우저 모드 61개 추가)
- `pnpm e2e`: 2 passed
- 데모 빌드를 `/con-ai/` 로 서빙해 Playwright 확인: 자격 증명 입력 → 배지 변경 → 생성 단계 진행 → succeeded → 새 revision 검토 화면 표시 → V3 not_run → 새로고침 후 유지 → 내보내기 6파일. 콘솔 오류 0
- 서버 모드(`pnpm serve`)에 영향 없음(브라우저 모드 코드는 일반 빌드에 포함되지 않음)

**남은 제한**
- **실제 모델 호출은 미검증**. 이 컨테이너는 브라우저 외부 접속이 막혀 모든 테스트가 fetch 주입이다. 실제 응답의 구조화 출력 수용 여부는 사용자 브라우저에서 처음 확인된다
- V3 실행 검사는 브라우저에서 불가하므로 `not_run`. 따라서 **완료(v1.0) 승인은 거부된다**(필수 검사 미실행). 정식 승인은 서버 실행에서만 가능하며, 브라우저에서는 미승인 상태로 파일을 내려받을 수 있다
- AS-IS 새 URL 분석 불가(다른 사이트를 캡처할 수 없다). 스냅샷의 기존 분석 결과만 보인다
- 여러 사람 공유 불가(브라우저별 저장). 더미데이터가 없는 화면은 빈 표로 렌더되고 unresolved 에 기록된다
- 모델 출력 JSON Schema 는 `packages/model-adapter/src/wire-schema.ts` 를 손으로 옮긴 것이라 한쪽을 고치면 같이 고쳐야 한다

## 화면설계서 시각 품질 개선 — 2026-09-05

**배경**: 생성되는 설계서가 "웹앱"처럼 보이고 설계 문서 품질에 못 미친다는 지적. 참고로 받은 BNK 프로토타입에서 화면설계서 30장을 추출해 목표 시각 언어를 정리했다(고객 자료이므로 저장소에 넣지 않고 작업용 임시 폴더에서만 참고).

**완료한 기능**
- 영역을 둥근 카드로 감싸고 좌상단에 바깥으로 걸친 검은 사각 번호 배지, 요소는 라벨 앞 파란 원형 배지
- 표는 회색 머리·얇은 테두리, 버튼은 검은 채움(주요)/흰 테두리(보조) 2단
- 상단 GNB(로고·활성 메뉴 밑줄·유틸)와 breadcrumb, 화면명 줄
- 우측 패널: 모노스페이스 화면 ID + 밑줄 → 개요 표(라벨 열 회색) → 절 라벨 → 영역 머리와 요소 한 줄(배지 + 이름 + 설명 + 구분선) → 검은 머리 메시지 표. 정책은 파란 막대 상자
- 모바일은 폰 프레임(상태 표시줄·햄버거 시트) 안에 렌더
- V2 구조 검사를 설명 영역 배지까지 확장하고 명세에 없는 배지를 탐지하도록 강화

**검증 결과**
- `pnpm check`: 테스트 643개 통과 / `pnpm e2e`: 2 passed
- 렌더 5종·CASE 전환·정렬·검색·모달·기기 전환에서 콘솔 오류 0, 산출 HTML 에 외부 참조 0
- 데모 스냅샷을 새 렌더러로 재생성하고 빌드 결과를 배포 경로로 서빙해 확인(검증 13건 표시, 콘솔 오류 0)

**남은 차이 (의도적)**
- 툴바·breadcrumb·상태 줄은 목표 문서에 없지만 CASE·기기 전환과 어댑터 표시 계약 때문에 유지
- 패널 절 순서는 계약(8절)을 따르므로 개요 표와 영역별 디스크립션 사이에 CASE·처리 흐름·정책·데이터 매핑이 들어간다

## 한 줄 입력 → 화면설계서 (기본 화면 단순화) — 2026-09-05

**배경**: "UI가 너무 어렵다. 제일 중요한 프로세스는 화면 설계가 HTML 로 되는 것". 생성 하나에 작업 유형·목적·범위·요구사항 체크·참고 화면·CASE·유지 조건·역할·기기를 모두 채워야 했다.

**완료한 기능**
- 기본 화면 `#/` 를 **만들기** 로 바꿨다: 문장 한 줄 + 기기 토글(PC 기본) + «설계서 만들기» 버튼 + 최근 만든 설계서 카드. 그 밖의 항목은 자동 기본값
- 화면 레코드를 자동으로 만든다: `POST /api/projects/:id/screens` (외부 ID `SCREEN-001`… 자동 부여, 중복 방지, zod 검증). 선택한 레퍼런스의 예시 더미데이터를 새 화면 이름(`SCREEN-001-normal` …)으로 복제해 표가 채워진 목업이 나온다
- 결과 화면 `#/d/:revisionId`: 설계서 HTML iframe(높이 78vh, 최소 70vh), «HTML 다운로드», «자세히»(기존 검토 화면), 버전 칩 v1·v2…, 이름 수정 필드(제목만 — 외부 ID·별칭은 그대로, `PATCH /api/screens/:id`), 한 줄 «수정»(내부적으로 `task_type:'edit'` + `base_revision_id` + `prompt_override`)
- 진행 표시는 한 줄("설계서를 만들고 있습니다 · 명세 작성 중"). 단계 이름·작업 ID·revision·artifact 같은 기술 용어는 기본 화면·결과 화면에 쓰지 않는다(«자세히» 화면에는 그대로)
- 실패는 사람 말 한 줄 + «다시 시도». 실패해도 이전 결과를 새 결과로 보여주지 않는다(문구로도 명시). 작업 id 는 주소(`?job=`)에 남겨 새로고침 후에도 진행·결과가 이어진다
- 자격 증명이 없는 정적 배포에서는 버튼을 누르면 **그 자리에서** 토큰 입력이 열리고, 저장하면 바로 생성이 이어진다(별도 패널로 보내지 않는다)
- 기존 홈(프로젝트·요구사항·IA·화면 목록)은 `#/advanced` 로 옮기고 기본 화면 우측 상단의 «고급» 링크로 연결. `#/screens/:id/generate|review|approve`, `#/references`, `#/asis` 와 그 testid·문구는 그대로
- 어댑터 표시는 기본 화면에도 남겼다: `더미 어댑터 (모델 호출 없음)` / `AI claude-opus-5` / `저장된 예시 보기 전용`(자격 증명 없는 데모)
- 브라우저 모드(demo-api)에도 같은 동작을 넣었다. 만든 화면·바뀐 제목은 localStorage 에 남아 새로고침 후에도 보인다

| 항목 | 값 | 근거 |
|---|---|---|
| `task_type` | `create` (결과 화면의 수정은 `edit`) | 기본 화면은 새 설계서를 만드는 자리다 |
| `purpose`·`prompt_override` | 입력 문장 그대로 | 서버는 `prompt_override` 가 있으면 그것을 지시로 쓰고 문맥은 그대로 첨부한다(계약 §2) |

| `device` | 토글 (PC 기본) | 화면의 유일한 선택지 |
| 화면 제목 | 첫 문장에서 부탁 표현을 떼고 30자 이내 | 결과 화면에서 바로 고칠 수 있다 |

## AS-IS 분석 화면 UI/UX 개선 — 2026-09-05

**배경**: "AS-IS 분석 화면의 메뉴가 가독성이 너무 떨어진다. 세련되게 다시 UI/UX 를 디벨롭해달라". 캡처(`.local/captures/A0-asis-list.png`·`A1-asis-detail.png`)로 확인한 문제는 네 가지였다.
1. 상단이 4겹(데모 배너 → 항상 펼쳐진 자격 증명 패널 → 내비 → 페이지 헤더 카드)이라 본문이 170px 아래로 밀렸다
2. 내비에 위계가 없었다 — 제품명·프로젝트명·메뉴 5개·배지 3개가 한 줄에 같은 무게로 붙어 있었다
3. 목록: 제목에 대시가 두 번(`AS-IS 분석 — 프로젝트명`), 같은 설명이 두 번, 1건짜리 목록을 표로 그렸다
4. 상세: 스크린샷이 위쪽을 차지하고 요약·페인포인트가 한참 아래, 구조 요약 14행에서 문제값이 정상값에 묻혔다, 페인포인트가 8열 표라 읽기 어려웠다

**완료한 기능 — 상단(전 화면 공통)**
- **자격 증명 패널을 기본 접힘**으로 바꿨다. 상단 바 오른쪽에 칩 하나(`내 토큰 ····1234` / `키 없음 — 스냅샷 데모`)만 두고, 누르면 상단 바 아래로 패널이 펼쳐지고 저장하면 닫힌다. 패널은 닫혀 있을 때도 DOM 에 남긴다(`hidden`) — `cred-panel`·`cred-status`·`cred-toggle` 등 기존 testid 의 뜻을 유지하기 위해서다
- 기존 진입 유지: `?help=key`(자격 증명 패널의 «Claude API 키 받는 법» 링크가 쓰던 쿼리)와 `?cred=open` 으로 들어오면 패널이 열린 채로 온다
- **내비 위계**: 왼쪽에 제품명(800 굵기) → 얇은 세로 구분선 → 메뉴. **프로젝트명은 내비에서 뺐다**(`project-name` testid 는 프로젝트 홈의 `<h2>`, AS-IS 목록의 메타 줄로 옮겼다). 현재 메뉴는 배경 박스가 아니라 **검은 밑줄 2px** — 설계서 GNB 와 같은 언어다
- **데모 배너는 내비 안으로 흡수**했다. 노란 띠를 내비 바로 위에 두면 색이 겹쳐 어디가 머리인지 흐려지므로, 앱 셸에서는 오른쪽 «정적 데모» 칩(무채색, title 에 전체 문구·저장소 링크)으로 대신하고 띠는 자체 상단 바를 쓰는 화면(메인·만들기·설계서)에만 무채색으로 남겼다
- 오른쪽은 상태 칩만: 자격 증명 · 정적 데모 · 어댑터 · Playwright. 긴 설명은 `title` 로 내렸다. **더미/실제 구분은 색이 아니라 문구로** 한다(«스냅샷 데모 · fixture 더미» / «fixture 더미 어댑터(모델 호출 없음)» / «실제 호출 · anthropic …»). 실제 모델 호출일 때만 파랑 강조 칩을 쓴다
- 결과: 상단 높이 **170px+ → 49px**, 본문 시작 y=49

**완료한 기능 — AS-IS 목록(`#/asis`)**
- 제목은 «AS-IS 분석» 한 줄 + 검은 사각 번호 배지 «1»(메인의 4단계 카드와 같은 표식). 프로젝트명·단계는 그 아래 작은 메타 줄
- **설명 중복 제거** — 리드 문단 한 곳에만 둔다
- 실행 폼: `대상 URL` 입력(모노) + «분석 실행» 을 **한 줄**로(Enter 로도 실행). 데모 대상 안내는 입력칸 아래 한 줄, 메모는 그 아래 보조 입력
- 목록은 표 대신 **행 카드**: URL 을 크게·모노로 두고 상태 배지·페인포인트 수·시각·메모를 한 줄 메타로 붙였다. 0건이면 빈 상태 안내

**완료한 기능 — AS-IS 상세(`#/asis/:id`)**
- 읽는 순서를 결론부터로 바꿨다: **헤더 → 요약 → 발견된 신호 → 페인포인트 → 스크린샷 → 구조 상세**
- 헤더: 대상 URL 이 제목(모노, 길면 줄바꿈). 상태·어댑터·소요·시각은 그 아래 **작은 한 줄 메타**(예전 4행 라벨/값 표를 없앴다). 소요 시간은 `asisDurationLabel` 로 계산하고, 시각이 없거나 뒤집혔으면 표시하지 않는다(0 으로 위장하지 않는다)
- **발견된 신호**(신설): 구조 요약 중 규칙에 걸린 항목만 골라 위로 올린다 — 레이블 없는 필드>0, alt 없는 이미지>0, h1 0건, 내비 링크>15, iframe>0, meta description 없음. 값(3개·0건·18개…)을 붉은 모노로 크게 두고 «왜 문제인지» 한 문장을 붙인다. 걸린 항목이 없으면 없다고 적는다
- 구조 요약 **전체 표는 접힘**으로 내렸다(`asis-structure-row` 는 그대로 — 문제값이 정상값에 묻히지 않게 자리만 바꿨다)
- **페인포인트: 표를 버리고 카드 목록**. 왼쪽 심각도 세로 스트라이프 / 머리줄(`PP-001` 모노 · 영역 · 심각도 배지 · 상태 배지 · 오른쪽 «채택»«거부» 가로 배치) / 설명(최대 70ch) / «근거» 모노 한 줄(90자 넘으면 접힘) / «제안» 문장
- **필터 칩**: 심각도(전체·높음·중간·낮음)와 상태(전체·제안·채택·거부), 오른쪽에 «제안 n · 채택 n · 거부 n» 집계. 기본값은 «전체» 라 순서·건수가 원본 그대로다
- 현재 상태인 버튼은 검은 «눌린 상태» 로 보인다(비활성이어도 흐려지지 않는다)
- 스크린샷은 페인포인트 아래로 내리고 데스크톱/모바일 토글을 유지, 최대 높이 560px + 내부 스크롤

**남은 제한**
- 심각도 표기는 기존 계약 문구(높음·중간·낮음)를 유지했다. 단위 테스트(`severityLabel`)와 API 응답이 이 낱말을 쓰고 있어 «심각·보통·낮음» 으로 바꾸지 않았다 — 색(빨강·주황·회색)만 요청대로 맞췄다
- 「발견된 신호」의 규칙(내비 링크 15개 초과 등)은 화면 표시용 임계값이다. 서버의 페인포인트 초안 규칙과 같은 기준을 쓰지만 두 곳에 따로 적혀 있다
- 모바일(390px)에서 상단 바는 4줄이 된다(제품명 / 메뉴 2줄 / 상태 칩). 정적 데모에서만 칩이 4개라 그렇고, 서버 모드에서는 칩 2개로 3줄이다. 고정(sticky)은 해제했다
- 스크린샷 카드는 데스크톱/모바일 두 장만 보여준다(계약 §12 의 두 뷰포트). 확대·전체 화면 보기는 없다

## P1-05 ID 레지스트리 · 추적 체인 REQ→IA→FN→SCR — 2026-09-06

산출물 `pipeline-v2.html` 의 12화면 중 **첫 번째**를 구현했다. 산출물 README 가 "이것 없이는 나머지 화면의
배지·커버리지가 모두 가짜가 됩니다" 라고 못박은 항목이다. 지금 앱에 **FN 계층이 아예 없어** 체인을 계산할
근거가 없던 것을 채웠다.

설계는 워크플로로 정했다: 5개 영역 병렬 정독 → 서로 다른 각도의 설계안 3종 → 규칙 준수·구현 리스크·산출물
충실도 3개 렌즈로 교차 심사 → 승자에 나머지 안의 아이디어를 접붙여 확정. 세 렌즈가 각각 다른 안을 골라
합계가 사실상 동률이었고, **어느 결함이 고칠 수 있는 것인가**로 갈랐다. 결정은 `docs/decisions/0015-*.md`.

**완료 기능**

| 계층 | 무엇을 더했나 |
|---|---|
| schemas | `id-registry.ts` — `IA-2.3.1`/`FN-2.3.1-02` 정규식, `IdIssuance`(by·at·reason **전부 필수**), `IdAlias`, `FunctionEntry`. `IANode` 에 optional 7필드(external_id·issued·aliases·requirement_ids·asis_ref·change_reason·functions) |
| domain | `id-registry.ts` — 번호 제안(순수)과 발번(행위자·사유 필수)을 분리. `rtm.ts` — 체인 집계·갭 제안·G1 추적성 판정 |
| api | `GET /api/projects/:id/rtm`(읽기), `GET·PATCH /api/ia-nodes/:id`, `POST …/id-issuances`, `POST …/id-relabels` |
| web | `#/trace` ID 매핑 화면 — KPI 5칸 · RTM 표 6열 · 갭 제안 + 사람 승인 · G1 판정 · 각주 |

**코드로 고정한 규칙 (CLAUDE.md)**
- **발번은 사람이 한다.** `IdIssuance` 의 세 필드가 모두 필수라 행위자 없는 발번은 parse 단계에서 불가능하다.
  부팅 시 자동 발번(backfill)은 만들지 않았다 — 그것이 이 화면의 존재 이유를 무력화한다.
- **서버가 번호를 다시 계산한다.** 요청값과 다르면 `differs` 로 알린다. 모델·클라이언트가 계산한 번호를 그대로 박지 않는다.
- **번호를 재사용하지 않는다.** 다음 번호는 현재 값과 별칭(옛 값)을 통틀어 본 최대값 + 1.
- **개명은 옛 값을 지우지 않는다.** `valid_to`·사유·행위자와 함께 별칭으로 내린다.
- **분모를 부풀리지 않는다.** 분모는 요구사항 수. 비UI 전용 REQ 를 분모에서 빼지 않는다(빼면 비율이 저절로 오른다).
  한 REQ 가 여러 화면에 걸쳐도 분자는 1. 분모 0 이면 비율은 `null`. 허용 키 가드로 INDEX 행 수 같은 값이
  입력에 들어오는 것을 실행 시점에도 막는다.
- **미실행을 통과로 표시하지 않는다.** 검증 완료는 숫자 0 이 아니라 `not_run` + 사유. 아직 생성되지 않은 화면의
  요소 태깅은 「0건」이 아니라 `not_run_screens` 로 분리.
- **없는 것을 빈칸으로 두지 않는다.** 미발번은 «(IA 코드 미발번)», 세지 못하는 것(출처·충돌·제외)은 각주에 자백.
- **`external-id.ts` 를 한 줄도 열지 않았다.** 그 모듈의 「생성 함수 없음」 불변식은 화면 external_id 에 대한 것이고,
  IA·FN 은 아직 아무 ID 도 없는 새 계층이라 두 규칙을 한 파일에 섞지 않았다.

**IA 번호 체계** (기획자 결정): 포털부터 3단. 파트너 포털 `IA-1` → 견적 `IA-1.1` → 견적 목록 `IA-1.1.1`.
카테고리 노드에도 번호를 준다. FN 은 소속 IA 번호를 이어받아 `FN-1.1.1-01`.

**시드** (기획자 결정): IA↔REQ 를 **일부만** 연결(목록←REQ-QT-001·004, 상세←REQ-QT-002)하고 FN·번호는 0건.
첫 화면이 「미매핑 · 갭 제안」 을 보여 주어야 무엇을 하는 화면인지 알 수 있기 때문이다.
이 배치는 골든 명세를 참고한 **개발용 합성 값**이지 실제 업무 매핑이 아니다(U-018).

**실행 방법**: `pnpm dev` → `#/trace` (좌측 레일 「자료 → ID 매핑」). 배포 주소에서도 동작한다 — 아래 항목 참고.

**검증 결과**

- 미확정 6건 추가: U-013(REQ 출처 분류) · U-014(요소 태깅 정본) · U-015(IA 재배치) · U-016(비UI G1) ·
  U-017(SCR 표기) · U-018(시드 배치의 임의성).

| 발번 제안에 초안 번호 | `proposeGapFills` 가 `suggested_value` 를 채운다(IA·FN 모두). 화면 입력칸이 비어 있어 사람이 번호를 짐작해야 하던 문제를 고쳤다 |
| 스냅샷 재생성 | `pnpm demo:snapshot` — 시드의 IA↔REQ 부분 연결이 스냅샷에 없어 배포에서는 전부 미매핑으로 보이던 것을 맞췄다 |

**코드로 고정한 규칙 (CLAUDE.md)**
- **더미와 실제를 구분해 적는다.** 화면 상단에 「이 브라우저 안에서 동작하고, 결과는 이 브라우저에만 남는다」를
  적는다. 계산 규칙이 서버와 같다는 사실도 함께 적는다 — 둘 다 사실이어야 의미가 있다.
- **저장 실패를 삼키지 않는다.** 사생활 보호 모드·용량 초과로 저장하지 못하면 응답에 `storage_warning` 을 싣고
  발번 알림에 이어 붙인다. 조용히 성공으로 보이게 두지 않는다.
- **저장 전에 같은 스키마로 막는다.** 브라우저에서도 `IANode` zod 스키마를 통과해야 저장한다.
- **발번은 여전히 사람이 한다.** 행위자·사유 없으면 도메인이 거절한다 — 데모라고 느슨하게 하지 않았다.
- **제안 번호는 초안이다.** `suggested_value` 를 넣되 저장할 때 다시 계산해 다르면 `differs` 로 알린다.

**부수로 고친 것**: `packages/domain/src/{id-registry,rtm}.ts` 와 `workers/generation/src/memory-store.ts` 의
문자열 안에 **원시 NUL 바이트**가 들어 있어 grep·diff 가 그 파일을 바이너리로 봤다. `\u0000` 이스케이프로 바꿨다
(동작은 같다).
