# 브라우저 모드 (내 토큰으로 실제 호출)

2026-09-05 (2026-10-10 갱신). GitHub Pages 정적 주소(<https://parkh37t.github.io/con-ai/>)에서 사용자가 **자기 Claude 자격 증명**을 넣으면 브라우저가 직접 `api.anthropic.com` 을 호출해 화면을 생성한다. 서버는 없다 — 이 페이지는 정적 파일 묶음이다.

**1순위는 내 Claude 구독 토큰**이다. `claude setup-token` (Claude Code CLI, 구독 필요 · 장수명)으로 받아 패널의 「내 구독 토큰」에 붙여넣는다. 콘솔 결제 수단·크레딧 설정이 필요 없다.
API 키(`sk-ant-…`)는 대안이며 사용한 만큼 과금된다.

구현 위치: `apps/web/src/browser-run/` (자격 증명·직접 호출·파이프라인·저장소), 통합은 `apps/web/src/demo-api.ts`. 일반 빌드(`pnpm build:web`)에는 이 코드가 들어가지 않는다(데모 코드는 동적 import 로 분리되어 서버 모드에서는 내려받지 않는다).

## 1. 쓰는 방법

1. 상단 **자격 증명 패널**에서 종류(내 구독 토큰 / API 키)를 고르고 값을 넣는다. 기본 선택은 토큰이다.
   - 기본은 **이 탭에서만**(sessionStorage). "이 브라우저에 저장" 을 켜면 localStorage 에 남는다.
2. 상단 배지가 `내 토큰으로 실제 호출 · claude-opus-5 · 토큰|API 키` 로 바뀐다.
3. 화면의 **생성 작업대**에서 평소처럼 목적·요구사항·CASE 를 고르고 "생성 실행" 을 누른다.
   단계(`문맥 구성 → 명세 생성 → 스키마 검사 → 렌더 → 검증 → 저장`)가 그대로 진행된다.
4. 결과 revision 은 검토·코멘트·수정 흐름을 그대로 탄다. 필수 검사(V3 포함)가 **실제로 통과하면** 완료(v1.0)까지 간다. 산출물은 서버 폴더가 없으므로 **파일로 내려받는다**(아래 3절).

자격 증명을 넣지 않으면 지금까지의 **스냅샷 데모** 그대로다(모델 호출 없음).

### 내보내기 파일 (계약 §8 과 같은 구성)

`index.html` · `spec.json` · `trace.json` · `validation.json` · `comments.json` · `manifest.json` 을 각각 Blob 으로 내려받는다(개별 버튼 + "모두 내려받기"). `manifest.json` 에는 `mode: "browser"` 와 파일별 sha256·검증 요약·디자인 이관 정보(`design_handoff`)가 들어간다.
승인 **전**에 내려받으면 `approved: false` · `version: null`, 승인 **뒤**면 `approved: true` · `version: "1.0"` 과 승인자·시각이 적힌다(`export-bundle.ts`). 승인되지 않은 묶음을 v1.0 산출물처럼 적지 않는다.

## 3. 저장되는 곳

| 데이터 | 위치 | 지우는 법 |
|---|---|---|
| 자격 증명 | 기본 sessionStorage(`con-ai:browser:credential`), "이 브라우저에 저장" 이면 localStorage | 패널의 "삭제" |
| 생성한 revision·명세·HTML·검증 결과, 코멘트, 승인 | localStorage `con-ai:browser:state` | 패널의 "브라우저 저장 데이터 지우기" |

- 저장 용량(브라우저마다 약 5MB)을 넘으면 `QuotaExceededError` 를 잡아 화면에 알린다. 저장에 실패해도 지금 보고 있는 화면은 계속 동작하지만 새로고침하면 사라진다.
- 사생활 보호 모드처럼 저장소 접근이 막힌 브라우저에서도 죽지 않는다(안내만 남기고 메모리로만 동작).

## 4. 보안 — 토큰을 어떻게 다루나

- **보관**: 사용자의 브라우저 저장소에만 둔다. 기본은 탭을 닫으면 사라지는 sessionStorage 다.
- **전송**: `https://api.anthropic.com/v1/messages` 요청 헤더에만 실린다. 다른 어떤 서버로도 보내지 않는다(보낼 서버가 없다 — 정적 파일이다).
  - 토큰(권장): `authorization: Bearer <값>` + `anthropic-beta: oauth-2025-04-20`
  - API 키: `x-api-key: <값>`
  - 공통: `anthropic-version: 2023-06-01`, `anthropic-dangerous-direct-browser-access: true`
- **표시**: 화면에는 종류와 **끝 4자리**만 보여준다. 값 전체는 다시 표시하지 않는다.
- **기록 금지**: 콘솔·오류 메시지·작업 문맥·저장 데이터·내보내기 파일에 값을 넣지 않는다. 모델 API 오류 문구에 값이 섞여 들어오면 한 번 더 가린다(redact). 이 규칙은 단위 테스트로 확인한다(`apps/web/src/browser-run/*.test.ts`).
- **공용 PC**: "이 브라우저에 저장" 을 켜지 말 것. 패널 안내 문구도 같은 내용을 적어 둔다.
- **서버 모드와의 차이**: 서버 모드(`pnpm serve`)에서는 모델 호출이 서버 어댑터(`packages/model-adapter`)에서만 일어나고 키는 서버 환경변수(`ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`)에서 읽는다. 브라우저에는 인증정보를 내려보내지 않는다(CLAUDE.md). 그래서 **자격 증명 패널은 정적 배포(`VITE_DEMO=1`)에서만 나타난다.**

## 5. CORS 근거

Anthropic API 는 브라우저 직접 호출을 허용한다. **토큰 경로의 헤더로** 프리플라이트를 확인했다(2026-10-10).

```bash
curl -X OPTIONS https://api.anthropic.com/v1/messages \
  -H "Origin: https://parkh37t.github.io" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: content-type,authorization,anthropic-version,anthropic-beta,anthropic-dangerous-direct-browser-access"
```

→ `HTTP/2 200` · `access-control-allow-origin: *` · `access-control-allow-headers` 에 요청한 다섯 헤더 전부(`authorization`·`anthropic-beta` 포함) · `access-control-allow-methods: DELETE, GET, HEAD, OPTIONS, PATCH, POST, PUT`.

**확인한 것은 프리플라이트뿐이다.** 자격 증명이 있는 실제 `POST` 는 이 컨테이너에 토큰이 없어 돌리지 못했다(`not_run`, 6절).

## 6. 검증한 것 / 검증하지 못한 것

**확인함**

- `pnpm check` (타입 검사 + 단위 테스트): 브라우저 파이프라인 단위 테스트 포함 — fetch 를 주입해 성공·401·429·거부(refusal)·스키마 실패 경로, V3 `not_run`(필수 여부 포함), 자격 증명 저장·삭제·끝 4자리 표시, 토큰이 저장 데이터·오류 메시지·프롬프트에 들어가지 않는지.
- `pnpm e2e` (서버 모드 2개) 그대로 통과.
- `pnpm demo:build` 결과를 `/con-ai/` 하위 경로로 서빙하고 Playwright 로 확인: 자격 증명이 없을 때 기존 데모 동작, 자격 증명을 넣었을 때(테스트에서는 `window.fetch` 를 가짜로 바꿔 주입) 생성 작업이 단계 진행 후 `succeeded` 되고 새 revision 이 검토 화면(Blob URL 격리 iframe)에 뜨는 것, V3 `not_run` 표시, 새로고침 후 결과 유지, 내보내기 6파일, 승인 거부 사유, **콘솔 오류 0**.
- 서버 모드(`pnpm build:web && pnpm start`)에서 자격 증명 패널·데모 청크가 로드되지 않고 fixture 배지가 그대로인 것.

**확인하지 못한 것 (사용자 브라우저에서 확인 필요)**

- **이 저장소(개발 컨테이너)에서는 실제 모델 호출을 검증하지 못했다.** 컨테이너의 브라우저는 외부 네트워크가 막혀 있어 모든 테스트가 fetch 를 주입해 동작을 재현한다. 따라서 아래는 사용자 브라우저에서 처음 확인된다.
  - 실제 응답에서의 구조화 출력 형태(`output_config.format` 의 JSON Schema 수용 여부, 응답 블록에서 JSON 을 꺼내는 경로).
  - 실제 401/429 응답 본문 문구, OAuth 토큰 경로(`anthropic-beta: oauth-2025-04-20`)의 동작. **프리플라이트는 이 헤더를 허용한다고 확인했지만(5절), 자격 증명이 붙은 실제 호출은 확인하지 못했다.**
  - AS-IS 페인포인트 초안의 실제 모델 경로(2026-10-10 추가). 단위 테스트는 fetch 를 주입해 성공·스키마 위반·401·429 를 모두 덮지만, 실제 모델이 첫 시도에 `WirePainPointDraft` 를 통과하는지는 사용자 브라우저에서 처음 확인된다.
  - 모델이 만든 명세가 첫 시도에 스키마·참조 검사를 통과하는 비율(실패하면 작업이 `schema_invalid`/`reference_invalid` 로 정직하게 끝난다).
- ~~JSON Schema 는 손으로 옮긴 것이다~~ — **더 이상 아니다.** 손으로 옮긴 복사본이 SDK 변환기와 계속 어긋나 실제 호출이 400 으로 죽었다. 지금은 생성물 한 벌(`packages/model-adapter/src/structured-schema.ts`, `pnpm gen:schema`)을 서버와 브라우저가 같이 쓰고, `structured-schema.test.ts` 가 매번 대조한다. **프롬프트 문구도 같은 이유로 한 벌만 둔다**(`prompts.ts`) — 같은 테스트가 서버·브라우저가 같은 상수를 쓰는지 확인한다.
- 더미데이터는 스냅샷에 들어 있지 않다. 브라우저 모드의 표는 **빈 배열**로 렌더되고 그 사실을 `unresolved(missing_evidence)` 로 남긴다.
