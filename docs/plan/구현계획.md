# 구현 계획 — 4단계 프로세스 기준

2026-09-05 · 방향 A(동작하는 세로 조각 먼저) 확정 후 작성. 설계 v0.2 의 §14 단계표는 참고로 두고, 아래 4단계 프로세스를 기준으로 재정렬한다.

## 목표 프로세스

| 단계 | 사용자 | 입력 | 산출 |
|---|---|---|---|
| ① AS-IS 분석 | 기획자 | 대상 서비스 URL·앱 | AS-IS 화면 캡처·구조, 페인포인트 목록 |
| ② 생성 | 기획자 | To-Be IA, 요구사항·수용조건, 참고 화면(포트폴리오), 프롬프트 | 화면명세(ScreenSpec) → HTML 목업 + 우측 설명, 검증 결과 |
| ③ 검토·수정 | 디자이너·퍼블리셔·개발자·고객·기획자 | 화면·설명 클릭 코멘트 | 수정 프롬프트(직접 또는 AI 자동) → 새 revision |
| ④ 완료·이관 | 기획자 → 디자이너 | 완료 버튼 | v1.0 HTML 묶음이 `exports/` 폴더에 저장, 디자인 이관 manifest |

## 세로 조각 v0 (지금)

샘플 프로젝트 하나로 ②→③→④ 가 브라우저에서 끝까지 동작한다.

| 구성 | 내용 | 완료 기준 |
|---|---|---|
| 샘플 데이터 | 와일리 컨버전스 본부용 가상 서비스 프로젝트: 요구사항 4~6건과 수용조건, To-Be IA, 화면 목록, 레퍼런스 포트폴리오(S2B 학습 규격을 적용한 목록·상세·팝업 골든 예시) | 첫 실행 시 자동 시드, 새로고침 후 유지 |
| 생성 작업대 | 대상 화면·작업 유형(신규/단건 수정/참조 복제)·목적·참고 화면·CASE·유지 조건 폼 → 자동 조립 프롬프트 미리보기 → 실행 | 작업 상태 queued→running→succeeded/failed 가 서버에 기록 |
| 모델 어댑터 | `anthropic`(실제 호출, 구조화 출력) / `fixture`(더미) 선택. 화면에 어떤 어댑터인지 표시 | 어댑터 출력은 서버에서 ScreenSpec 스키마·참조 재검사 |
| 렌더러 | ScreenSpec → 오프라인 HTML(목업 + 우측 설명, CASE 전환, 더미 검색·정렬·팝업·다운로드) | 같은 명세에서 UI 와 설명 생성, 요소에 `data-element-id` |
| 검증 | V1 명세, V2 렌더 구조, V3 실행(Playwright) | 4상태 기록, fixture 의 잘못된 매핑·누락 CASE 가 fail |
| 화면 검토 | 격리 iframe 미리보기, CASE·PC/모바일 전환, 요소·설명 클릭 → 코멘트(역할·작성자·artifact hash·요소·CASE 고정) | 코멘트가 새로고침 후 유지 |
| 수정 | 코멘트 → "AI 수정 프롬프트 생성" 또는 직접 입력 → 단건 수정 작업 → 새 revision, 변경 요약, 코멘트 해결 표시 | 이전 HTML 을 새 결과처럼 보이지 않음 |
| 완료·이관 | 승인 판정(필수 검사 pass, hash 일치, 차단 코멘트 0) → v1.0 → `exports/<프로젝트>/<화면>/v1.0/` 저장(index.html, spec.json, trace.json, validation.json, comments.json, manifest.json) | 폴더를 열어 바로 볼 수 있는 HTML, 디자인 이관 필드(design_input_spec_hash, 잠긴 요소) |
| 검사 | `pnpm check` + Playwright e2e 1개(생성→코멘트→수정→완료) | 통과 |

## 이후 단계

1. **AS-IS 분석 에이전트**(①): URL 입력 → Playwright 캡처·구조 추출 → 페인포인트 초안 → 기획자 확정. To-Be IA 와의 연결.
2. **다중 화면·프로젝트 운영**: 화면 목록·IA 편집, 요구사항 XLSX 수입(설계 §4 가져오기 설정), 매핑 작업대, 커버리지.
3. **품질**: V4 표시·접근성, V5 회귀(잠긴 요소), 사람 검토 기록, 변경 영향(stale).
4. **디자인 에이전트 연계**: 이관 manifest 를 받는 디자인 단계(설계 §12).
5. **운영화**: PostgreSQL 전환, 권한, 작업 큐 분리(workers/generation), 배포.

## 준비 단계(0)에서 끝난 것

- 골격, 검토 데이터 취급 규칙, CSV 파서·무결성 테스트
- `packages/schemas` 68 테스트, `packages/domain` 38 테스트, `fixtures` 51 테스트 — 세로 조각의 검증 장치로 사용
- 지식 문서 4개(`docs/knowledge/`), 규칙 요약은 `CLAUDE.md`

## 측정

생성 시간뿐 아니라 검토·수정 왕복 횟수, 코멘트 해결까지 걸린 시간, 검증 실패율, 화면당 모델 비용을 기록한다(설계 §14). 기준값은 세로 조각 완성 후 첫 파일럿에서 잡는다.
