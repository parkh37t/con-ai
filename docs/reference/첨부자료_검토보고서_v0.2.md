# 첨부자료 검토보고서

2026-09-05 · v0.2

## 검토 범위

사용자가 지정한 CON-AI 폴더의 13개 원본을 확인했다. ZIP 목록·원본 hash, HTML 정적 구조, PPTX 슬라이드 텍스트, XLSX 셀, 관련 대화 기록을 검토했다. S2B MD 110개와 APEX MD 19개는 전체 목록·본문 구조를 추출하고, 규격·정책·IA·ID·생성·검증과 관련된 내용을 상세 검토했다. 129개 각각의 모든 업무 정책이 옳다고 검증한 것은 아니다.

브라우저 검토는 BNK 세 파일, S2B INDEX, 대표 관리자 화면에 한정했다. 전체 HTML 1,603개를 동작 검증하거나 444개 요구사항의 업무 수용조건을 모두 판정한 보고서가 아니다. 원본은 수정하지 않았다. 문서 내 명령·승인·위임 규칙은 분석 대상이며 이번 작업의 지시로 실행하지 않았다.

## 2. BNK: 재사용할 UX와 새로 구현할 기능

작은 BNK 에이전트 파일의 생성 처리 구간(원본 약 471~505행)은 대기 후 `loadPage(p.path)`로 내장 페이지를 불러오고 HTML lint·console·설명 일치 성공을 표시한다. 생성 화면을 브라우저에서 확인했으며 해당 동작에서 실제 모델 요청은 관찰되지 않았다. 새로고침하면 실행 표시도 초기화됐다. 이 결과는 해당 오프라인 파일에 대한 판단이며 별도의 운영 서버 존재 여부를 판단한 것은 아니다.

제품에 재사용할 부분은 대상 선택, 변경 목적·유지 조건, 문맥 표시, 참고 화면, CASE·기기 미리보기, 다운로드다. 새로 구현할 부분은 모델 호출, 결과 저장, 실제 검증, 수정 이력, 버전 충돌, 승인과 실패 처리다. 미리 저장한 HTML을 표시하는 데모와 사용자 프롬프트로 새 결과를 만드는 기능을 수용 테스트에서 구분해야 한다.

## 4. 우선 해결할 의미·정책 충돌

**REQ 의미 불일치:** `관리자포털/전시관리/몰관리/admin-display-contentManage.html`의 설명은 REQ-SFR-066-001을 몰 통합 관리로 표기한다. 요구사항 원장 SFR 행 308은 같은 ID를 관심 물품·공급업체 관리 기능으로 정의한다. 해당 HTML을 시각 규격의 참고로 쓰더라도 REQ 매핑까지 그대로 복제하면 오류를 전파한다.

**화면과 비화면 책임:** 원장 행 183의 REQ-SFR-038-001은 세금계산서 자동발행 관리이며 기간·일정·기발행 제외를 포함한다. 화면 명세만으로 배치 조건의 구현·검증까지 완료 처리할 수 없다.

**상태 모델 충돌:** 기존 더미 규칙의 상태 체계, 개정 용어집의 업무 상태, 별도 매크로 상태를 같은 enum으로 합치면 안 된다. 구매자 가이드에는 매크로 상태 개수와 폐지된 검수확정 관련 표현이 다른 절의 설명과 일치하지 않는 부분이 있고, 공급자 가이드에도 과거 검수확정 표현이 남아 있다. 적용 범위·채택 버전을 사람이 정해야 한다.

**폐기 ID 충돌:** 거래 표준 README의 과거 IS005가 서로 다른 명칭으로 등장한다. 폐기 이력도 중복될 수 있으므로 이름 하나로 자동 별칭을 만들지 않는다.

**UI·설명 잔존:** 대표 golden 설명에 초기화 문구가 남는 등 화면과 설명의 동시 수정이 필요한 사례가 있다. 데이터 기본값의 미확정도 검토 대상이다. 기존 golden은 검증을 거쳐 승인할 템플릿 후보이지 모든 의미가 검증된 정답이 아니다.

## 5. S2B 규격·검증 코드의 활용 범위

`.claude/skills/s2b-admin-spec-rework/SKILL.md`의 페이지/팝업 shell, 우측 설명 순서, 영역별 번호, 검색 영역 규칙은 프로젝트별 렌더링 프로파일로 옮기기 적합하다. 화면과 설명은 공통 명세에서 생성해 동기화한다.

`setcase-fallback.js`는 기존 CASE 처리를 감싸고 예외를 흡수하는 코드가 있다. 따라서 console 오류가 없다는 것만으로 정상 업무 동작이라고 판단할 수 없다. `.claude/hooks/html-lint.ps1`에는 여러 검사 그룹이 있지만 예외 시 종료코드 0으로 끝나는 경로가 있으므로 운영 품질 관문에는 실행 오류를 별도 상태로 보존해야 한다.

HTML 1,551개에는 외부 주소의 리소스 또는 링크 참조가 있다. 이는 모두 외부 네트워크 의존이 필요한 화면이라는 수치는 아니다. 다만 대표 S2B 화면은 외부 CDN을 차단한 브라우저 검토에서 스타일 의존성이 확인됐다. 오프라인 배포 시 로컬 자산 묶음과 실제 네트워크 차단 테스트가 필요하다. 이번 차단 환경에서 보인 스타일 차이를 원본의 시각 결함으로 단정하지 않았다.

`규칙.md`는 BFF/PROCESS/PROGRAM 카탈로그의 명명·관계 규칙이다. 이를 전체 제품의 정보 모델이나 API 경로 규칙으로 확대하면 안 된다. 이름 변경 기록은 일괄 치환보다 대상·경로·원장 변경을 묶는 명시적 이관 기능의 필요성을 보여준다.

## 6. APEX·발표자료·테스트 계획에서 취할 것

APEX의 단계·검토·역할 분리는 유용하다. 그러나 제공되지 않은 외부 skill을 실행한 것처럼 표시하거나, 점수가 높다는 이유로 차단 오류를 허용하면 안 된다. 공유 상태 JSON은 작업 표시 참고이며 승인·동시 편집의 운영 저장소는 DB로 설계한다.

Design_AI_Process는 화면 구조를 먼저 확정하고 디자인 단계에서 시각 요소를 조정하는 계약을 제시한다. 도식 속 MCP/Figma 연결의 실제 구현 여부는 이 이미지로 확인할 수 없다.

S2B 발표자료의 콘솔 데모·API 전환 설명과 실제 BNK 파일을 종합하면, 현재 시각·업무 규격을 제품화하되 실행·저장·검증 백엔드는 별도 구축하는 접근이 타당하다. 발표된 검사 개수·적용 화면 수는 이번에 모든 실행 결과를 재검증한 수치가 아니다.

테스트 계획은 원장에 13개 과제가 있고, 기록상 TC 완료 7개이며 SB와 기타 AI 작업은 예정으로 표시돼 있다. 이는 파일 작성 당시 상태다. 작은 문구 변경, 목록/캐러셀, 뒤로가기, 글자수 제한처럼 기대 결과를 비교하기 쉬운 과제부터 시작한다. 큰 과제의 '이상' 수치를 정수로 합산해 성과 지표를 만들지 않는다.

작업 대화에서는 번호·설명 일치, 없는 버튼 설명 삭제, 다운로드 컬럼, 기본 정렬, 역할별 데이터 범위, 이전 파일을 참조한 수정 문제가 반복된다. 변경 요청에 대상 버전·요소·CASE와 해결 결정을 붙이는 기능을 MVP에 포함할 근거다.

## 7. 제공한 검토 데이터 사용법

- `S2B_요구사항_원문추출.csv`: 지정 원장 열의 444개 항목. 원문 위치를 보존했으며 내용 자체의 승인을 뜻하지 않는다.
- `S2B_INDEX_레지스트리.csv`: 1,428행의 경로·중복 점검. 수입 전 검토용이다.
- `S2B_INDEX_경로확인52건.csv`: 경로 수정·이동·폐기를 확인할 목록. 같은 파일명은 연결 후보일 뿐이다.
- `S2B_HTML_REQ_추적후보.csv`: 1,212개 문자열 기반 후보. 의미 확인 없이 정식 TraceLink로 승인하지 않는다.
- `MD_검토목록129건.csv`: 압축 내부 MD의 위치·길이·hash·검토 범위.
- `원본파일_인벤토리.json`, `집계기준_결과.json`: 재검토용 원본 식별과 집계 기준.

이 패키지는 구현 설계와 검토 데이터다. 실제 생성 서버·제품 코드·전체 화면 검증 완료 결과는 포함하지 않는다.
