# 0015. FN 계층을 IA 노드 문서 안에 두고, 「요소는 FN·IA 없이 저장 불가」는 G1 미통과로만 강제한다

- 상태: 채택 (2026-09-06)
- 맥락: 산출물 pipeline-v2 의 P1-05「ID 매핑 매트릭스」= 추적 체인 REQ → IA → FN → SCR 구현.

## 결정 1 — FN 은 `IANode.functions[]` 안에 산다 (별도 문서 종류를 만들지 않는다)

산출물 ID 표는 「FN 은 IA 1개에만 소속」이라고 못박는다. FN 을 별도 문서로 두면 그 규칙을
**교차참조 검사**로 지켜야 하고, 검사를 빠뜨리면 두 IA 에 매달린 FN 이 저장된다.
IA 문서 안 배열로 두면 같은 규칙이 **저장 위치의 불변식**이 된다 — 한 문서 안에만 존재하므로
두 IA 에 동시에 있을 수 없다.

대가: 같은 IA 아래 두 사람이 서로 다른 FN 을 동시에 발번하면 문서 revision 충돌로 한쪽이 409 를 받는다.
P1-05 는 여러 명이 갭을 메우는 화면이라 이 경합이 정확히 이 화면에서 난다. 지금은 감수하고
화면이 새로고침을 안내한다. 마찰이 실제로 문제가 되면 그때 별도 문서로 분리하고 교차검사를 추가한다.

## 결정 2 — 요소 태깅은 FN → 요소 방향(`element_refs`)이다

「요소는 FN·IA 없이 저장 불가」를 ScreenSpec 쪽(요소에 `fn_id` 필수)으로 표현하면
`wire-schema.test.ts` 가 `WireScreenSpec.shape` 와 `ScreenSpecShape.shape` 의 키 완전 일치를 단언하므로
optional 필드 하나만 더해도 wire-schema → browser-run → prompt-templates → renderer → fixtures 4종 →
examples 3종이 한 커밋에 끌려온다. 그 커밋에는 중간에 `pnpm check` 가 통과하는 지점이 없다.

그래서 이번 조각은 ScreenSpec 을 **한 줄도 건드리지 않고** FN 이 요소를 가리키게 했다.
대가: 화면을 다시 생성해 요소 ID 가 바뀌면 태그가 고아가 된다. RTM 이 `refs_stale` 로 보고하지만
자동 복구하지 않는다(사람이 다시 연결한다). 정본을 ScreenSpec 으로 옮길지는 미확정(U-014).

## 결정 3 — 저장 차단이 아니라 G1 미통과로 강제한다

파이프라인의 `checkSpec(result, built, stage)` 에는 store 가 없어 저장 시점에 IA·FN 을 조회할 수 없고,
V1 검사에 새 항목을 넣으면 `REQUIRED_CHECKS` 가 V1_CHECKS 를 그대로 펼치므로 즉시 승인 필수 검사가 되어
`v1.test.ts` 의 배열 단언과 fixtures 4종이 함께 움직인다.

따라서 이번 조각에서 「요소는 FN·IA 없이 저장 불가」는 **저장 차단이 아니라 G1 추적성 미통과**로만 나타난다.
그 사실을 RTM 화면 각주·진행기록에 그대로 적는다. 나중에 V1 에 편입할 때는 무조건 필수가 아니라
`requiredChecksFor`(validators/index.ts)의 **조건부 필수** 패턴이어야 한다 — 기존 fixture 에는
trace 조차 없는 요소가 있다.

## 결정 4 — 발번은 사람이 하고, 서버가 번호를 다시 계산한다

에이전트는 제안만 만든다. 발번 요청은 행위자·사유·시각이 모두 있어야 스키마 파싱을 통과한다
(`IdIssuance`). 승인 시점에 서버가 `proposeIaExternalId`/`proposeFnExternalId` 로 번호를 **다시 계산**하고,
요청값과 다르면 응답에 `differs` 를 실어 화면이 「제안한 번호와 다른 번호가 발번되었습니다」를 보여 준다.
모델이나 클라이언트가 계산한 번호를 그대로 박지 않는다.

부팅 시 자동 발번(backfill)은 **만들지 않는다.** 사람 승인 없는 발번이기 때문이다.
기존 DB 는 커버리지 0%·미발번 상태로 정직하게 시작하고, 사람이 화면에서 채운다.

## 결정 5 — IA 번호는 포털부터 3단 (기획자 결정)

파트너 포털 = `IA-1`, 견적 = `IA-1.1`, 견적 목록 = `IA-1.1.1`. 카테고리 노드에도 번호를 준다.
산출물 예시 `IA-2.3.1` 과 같은 형태가 된다. FN 은 소속 IA 번호를 그대로 이어받아 `FN-1.1.1-01`.

알려진 대가: IA 를 재배치하면 이미 발번된 번호와 트리 위치에서 다시 계산한 제안값이 어긋난다.
자동 개명은 CLAUDE.md 위반이므로 하지 않는다. 지금은 발번 응답의 `differs` 로 알리기만 한다(U-015).
